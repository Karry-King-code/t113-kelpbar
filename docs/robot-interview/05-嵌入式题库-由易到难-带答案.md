# 第一级 ★ 入门（Linux 命令 + GCC/GDB + C 基础）（23 题）

### 1. Linux 从通电到进入 shell 的启动流程？
<details><summary>📝 点开看答案</summary>

嵌入式典型流程：**BootROM（芯片固化）→ Bootloader（U-Boot：初始化内存/存储/串口，把内核读到内存，把设备树地址传给内核）→ Linux 内核（初始化驱动、挂载根文件系统）→ init/systemd（PID 1）→ 登录 shell**。

面试加分：说出"引导期读 FEX/环境变量，内核期读设备树"——两段各读各的配置。
</details>

### 2. `ps` 和 `top` 的区别？
<details><summary>📝 点开看答案</summary>

- `ps`：**快照**，看某一刻的进程列表（`ps aux` / `ps -ef`），适合配合 grep 查进程。
- `top`：**动态刷新**，看 CPU/内存占用实时排行，适合看谁在吃资源。
- 补充：`top -H` 看线程；`kill -9 PID` 强杀。
</details>

### 3. `df` 和 `du` 的区别？磁盘满了怎么查？
<details><summary>📝 点开看答案</summary>

- `df -h`：按**文件系统**统计总容量/已用/可用（看分区满没满）。
- `du -sh 目录`：按**目录/文件**统计占用（找谁占的）。
- 排查：先 `df -h` 确认哪个分区满 → `du -sh /* 2>/dev/null | sort -h` 逐层定位；注意**已删除但被进程占用的文件**（`lsof | grep deleted`）。
</details>

### 4. 硬链接和软链接的区别？
<details><summary>📝 点开看答案</summary>

| | 硬链接 | 软链接 |
|---|---|---|
| 本质 | 多个目录项指向**同一 inode/同一份数据** | 独立文件，内容是**目标路径字符串** |
| 跨文件系统 | 不行 | 可以 |
| 链接目录 | 不行 | 可以 |
| 删源文件 | 数据仍在（链接数-1，为 0 才删） | 链接悬空、打不开 |

`ln a.txt b` 建硬链接；`ln -s a.txt b` 建软链接。

**项目延伸**：`sed -i` 处理软链接会**销毁链接、原地生成普通文件**——于是"验证读新文件、编译读真身"，这是本项目真实踩过的坑。
</details>

### 5. `chmod 755` 是什么权限？`/etc/shadow` 为什么是 640/600？
<details><summary>📝 点开看答案</summary>

755 = 所有者 `rwx`(7)、组 `r-x`(5)、其他 `r-x`(5)。即所有者可读写执行，其他人只能读和执行。

`/etc/shadow` 存密码哈希：**普通用户绝不能读**，只有 root 可写，所以 640（root 读写、shadow 组读）或 600（仅 root）。
</details>

### 6. `find` 的三个常用用法？
<details><summary>📝 点开看答案</summary>

```bash
find . -name "*.log"                 # 按名字
find / -size +100M                   # 大于 100MB
find . -mtime -7                     # 7 天内修改过
find . -type f -name "*.c" -exec grep -l "main" {} \;   # 组合
```
注意：`-mtime -7` 是"7 天内"，`+7` 是"7 天前"。
</details>

### 9. `mount` / `umount` 的作用？U 盘挂载流程？
<details><summary>📝 点开看答案</summary>

把块设备挂到目录树某个挂载点。
```bash
lsblk                       # 找设备，如 /dev/sdb1
sudo mount /dev/sdb1 /mnt   # 挂载
sudo umount /mnt            # 卸载（必须先退出该目录、无进程占用）
```
`umount: target is busy` → `lsof +f -- /mnt` 找占用进程。
</details>

### 10. `grep`/`sed`/`awk` 各擅长什么？

</details>

### 12. `PATH`、`PS1` 是什么？`export` 作用？
<details><summary>📝 点开看答案</summary>

- `PATH`：命令搜索路径，`echo $PATH` 查看；`export PATH=$PATH:/opt/bin` 追加。
- `PS1`：shell 提示符格式（如 `\u@\h:\w\$`）。
- `export`：把变量导出为**环境变量**，子进程可见；不加 export 只是当前 shell 的普通变量。
</details>

### 13. `>`、`>>`、`2>&1`、`|` 的区别？
<details><summary>📝 点开看答案</summary>

- `>` 覆盖重定向标准输出；`>>` 追加。
- `2>&1` 把标准错误（fd 2）也指向标准输出（fd 1）的位置。
- `|` 管道：前一个命令的输出作为后一个的输入。
- `ls notexist > /dev/null 2>&1`：**丢弃标准输出和错误**，命令失败也静默。
</details>

### 14. `&`、`nohup`、`jobs`、`fg` 的区别？
<details><summary>📝 点开看答案</summary>

- `&`：放到后台运行，但**终端关闭/SSH 断开会被 SIGHUP 杀掉**。
- `nohup cmd &`：忽略 SIGHUP，断开后继续跑（输出默认到 nohup.out）。
- `jobs`：看当前 shell 的后台任务；`fg %1` 调回前台；`bg` 让暂停的任务后台继续。
- 更稳：`setsid` / `start-stop-daemon` / systemd 服务。
</details>

### 15. 什么是交叉编译？为什么嵌入式必须用？
<details><summary>📝 点开看答案</summary>

在 **x86 PC 上用 ARM 编译器**编译出 ARM 板能执行的程序。因为板子 CPU 弱、内存小，跑不动编译器；而且目标板的库/头文件与 PC 不同。

确认产物架构：`file app` → 应显示 `ELF 32-bit ... ARM`。配套环境变量：`STAGING_DIR` 指向目标板库。
</details>

### 16. `static` 修饰局部变量、全局变量、函数分别什么效果？
<details><summary>📝 点开看答案</summary>

- 局部变量：生命周期变为**整个程序**（存全局数据区），只初始化一次，函数退出不销毁。
- 全局变量/函数：**作用域限制在本文件**（内部链接），避免命名冲突。
- 记忆：static = "延长寿命"（局部）+ "限制范围"（全局/函数）。
</details>

### 17. `volatile` 的作用？三个场景？能保证线程安全吗？
<details><summary>📝 点开看答案</summary>

告诉编译器**每次都要从内存读**，不许优化进寄存器或重排。

三个场景：①内存映射的硬件寄存器；②中断服务程序与主程序共享的变量；③多线程共享但无锁的标志位（仍不保证原子）。

**不能保证线程安全**：volatile 只解决"可见性/不被优化"，不保证原子性和互斥。
</details>

### 18. `const int *p` 与 `int * const p` 的区别？
<details><summary>📝 点开看答案</summary>

- `const int *p`：**指向的内容不能改**，指针本身可以改指向（`*p = 1` 错，`p = &x` 对）。
- `int * const p`：**指针本身不能改**，内容可以改（`p = &x` 错，`*p = 1` 对）。
- `const int * const p`：都不能改。
- 口诀："左定值，右定向"（const 在 * 左边管值，在右边管指针）。
</details>

### 19. 结构体字节对齐规则？`char+int+short` 占多少？
<details><summary>📝 点开看答案</summary>

规则：①每个成员相对结构体首地址的偏移必须是**该成员大小**的整数倍（有 `#pragma pack(n)` 时取 min(成员大小, n)）；②结构体总大小必须是**最大成员大小**的整数倍。

```c
struct S { char a; int b; short c; };   // 32 位
// a@0, 填充3字节, b@4, c@8, 总10 → 补齐到4的倍数 = 12
```
</details>

### 20. `#pragma pack(n)` 的作用与风险？
<details><summary>📝 点开看答案</summary>

改变结构体最大对齐字节数（按 n 字节对齐），用于**协议帧、寄存器映射**等必须紧凑的场景。
风险：①访问未对齐内存在某些架构（ARM 旧核）会异常或变慢；②跨平台数据交换时双方必须一致，否则解析错位。
</details>

### 21. ### GCC 编译的四个阶段是什么？各阶段用什么命令？
<details><summary>📝 点开看答案</summary>

**预处理 → 编译 → 汇编 → 链接**

| 阶段 | 做什么 | 命令 | 产物 |
|---|---|---|---|
| 预处理 | 宏替换、头文件展开、条件编译、删注释 | `gcc -E test.c -o test.i` | test.i |
| 编译 | 词法/语法/语义分析，翻译成汇编 | `gcc -S test.i -o test.s` | test.s |
| 汇编 | 汇编转机器码 | `gcc -c test.s -o test.o` | test.o |
| 链接 | 合并目标文件、解析外部引用（库函数） | `gcc test.o -o test` | 可执行文件 |

一步到位：`gcc test.c -o test`。常用：`-Wall` 显示所有警告、`-g` 生成调试信息（配合 gdb）。
</details>

# 第二级 ★★ 进阶（内存 + 进程线程 + 文件/网络 IO 基础）（39 题）

### 24. C 程序内存分哪五区？
<details><summary>📝 点开看答案</summary>

①**栈**：局部变量、函数参数、返回地址，自动分配释放，向下增长；
②**堆**：malloc/free，手动管理，向上增长；
③**全局/静态区**（.data 已初始化 + .bss 未初始化）：全局变量、static 变量；
④**常量区**（.rodata）：字符串字面量、const 全局；
⑤**代码区**（.text）：机器指令，只读。
**static 局部变量在全局/静态区**（不在栈上）。
</details>

### 25. `malloc` 的底层流程？`malloc(0)` 返回什么？
<details><summary>📝 点开看答案</summary>

流程：用户态 malloc → 小内存从**堆**（brk 扩展）或**内存池**分配；大内存（>128KB）用 **mmap** 映射 → 返回**虚拟地址** → 首次访问触发**缺页异常** → 内核分配物理页并建页表映射。

`malloc(0)`：实现相关，**可能返回非 NULL 的可 free 指针**，也可能返回 NULL；不要依赖。
</details>

### 26. 数组名和指针的区别？什么时候退化？
<details><summary>📝 点开看答案</summary>

- 数组名是**数组首元素地址**，是常量，不能赋值；`sizeof(arr)` 是数组总字节数。
- 指针是变量，可赋值，`sizeof(p)` 是指针大小（32 位=4）。
- 数组名在**作为函数参数、参与运算、赋给指针**时退化为指针（丢失长度信息）。
</details>

### 27. 函数指针与指针函数的区别？用函数指针实现状态机？
<details><summary>📝 点开看答案</summary>

- **指针函数**：返回指针的函数，`int *f()`。
- **函数指针**：指向函数的指针，`int (*f)(int)`。
- 状态机：
```c
typedef void (*state_fn)(void);
state_fn table[] = { state_idle, state_run, state_err };
table[current_state]();
```
</details>

### 28. 统计一个字节里 1 的个数；置位/清位？
<details><summary>📝 点开看答案</summary>

```c
int count(unsigned char v) {
    int n = 0;
    while (v) { n += v & 1; v >>= 1; }
    return n;
}
// 更快：n = v - ((v>>1)&0x55); n = (n&0x33)+((n>>2)&0x33); n = (n+(n>>4))&0x0F;
reg |=  (1u << 3);     // 第3位置1
reg &= ~(1u << 5);     // 第5位清0
reg ^=  (1u << n);     // 翻转
if (reg & (1u << n))   // 判断
```
</details>

### 29. 进程和线程的区别（至少 4 个维度）？
<details><summary>📝 点开看答案</summary>

| 维度 | 进程 | 线程 |
|---|---|---|
| 定义 | 资源分配单位 | CPU 调度单位 |
| 地址空间 | 独立 | 共享所属进程 |
| 切换开销 | 大（换页表、TLB、缓存） | 小（只换寄存器和栈） |
| 通信 | 需 IPC | 直接共享内存（要同步） |
| 崩溃影响 | 互不影响 | 一个崩全进程死 |
</details>

### 30. 多进程和多线程各自的优缺点？
<details><summary>📝 点开看答案</summary>

- 多进程：隔离好、稳定（一个崩不影响其他）、可利用多核；缺点：创建/切换开销大、通信麻烦。
- 多线程：轻量、通信方便、共享数据快；缺点：需同步（锁）、一个线程崩全进程死、调试难。
- 选择：机器人/服务端常用"多进程做隔离 + 进程内多线程做并发"。
</details>

### 31. 进程有哪几种状态？怎么转换？
<details><summary>📝 点开看答案</summary>

基本五态：**创建 → 就绪 → 运行 → 阻塞（等待）→ 终止**。
- 运行 → 就绪：时间片用完/被抢占
- 运行 → 阻塞：等待 I/O 或事件
- 阻塞 → 就绪：事件到达
- 就绪 → 运行：被调度
</details>

### 32. 僵尸进程、孤儿进程、守护进程？
<details><summary>📝 点开看答案</summary>

- **僵尸**：子进程已退出，父进程没 wait 回收，进程表项残留（占 PID）。解决：父进程 wait/waitpid。
- **孤儿**：父进程先退出，子进程被 init/systemd 收养。
- **守护进程**：脱离终端、后台长期运行（fork 两次 + setsid + 重定向标准流）。
</details>

### 33. `fork()` 为什么返回两次？写时复制？
<details><summary>📝 点开看答案</summary>

fork 创建子进程，**父子都从 fork 之后继续执行**：父进程返回子 PID（>0），子进程返回 0，失败返回 -1。

**写时复制（COW）**：fork 时父子共享同一份物理页（只读），任一方写入才复制该页——省内存、加快 fork。
</details>

### 34. 进程间通信有哪些方式？适用场景？
<details><summary>📝 点开看答案</summary>

- 管道/命名管道：简单字节流，亲缘/任意进程
- 消息队列：有格式消息，松耦合
- **共享内存**：最快（零拷贝），需配信号量同步
- socket：可跨机器（本机用 Unix 域）
- 信号：异步通知（SIGTERM/SIGKILL）
- 信号量：同步/互斥（不算传数据）
</details>

### 35. 线程同步有哪些手段？互斥锁和信号量区别？
<details><summary>📝 点开看答案</summary>

互斥锁、读写锁、条件变量、信号量、原子操作、自旋锁。
- **互斥锁**：二值、谁加锁谁解锁（所有权），用于临界区互斥。
- **信号量**：计数器，可 >1（控制并发数），可由别的线程 post（无所有权）。
</details>

### 36. 死锁的四个必要条件？怎么避免？
<details><summary>📝 点开看答案</summary>

互斥、占有且等待、不可剥夺、循环等待。
避免：**统一加锁顺序**（最实用）、加锁超时、一次性申请全部资源、避免持锁调用外部接口。
</details>

### 37. 用户态和内核态怎么切换？系统调用流程？
<details><summary>📝 点开看答案</summary>

CPU 分 Ring 0（内核）/Ring 3（用户）。切换方式：**系统调用、中断、异常**。
syscall 流程：用户态把参数放寄存器/栈 → 触发软中断/`svc` 指令 → 陷入内核 → 查系统调用表执行内核函数 → 返回用户态（`ret`/`iret`）。
</details>

### 38. 虚拟内存有什么用？分页的好处？
<details><summary>📝 点开看答案</summary>

作用：①进程地址空间隔离；②可运行比物理内存大的程序（换页）；③内存保护（只读/可执行）；④简化链接与内存分配（连续虚拟地址映射到不连续物理页）。
分页好处：消除外部碎片、按页管理、支持换出/共享。
</details>

### 39. 页表怎么转换虚拟地址？TLB 是什么？
<details><summary>📝 点开看答案</summary>

32 位两级页表：虚拟地址 = **页目录索引(10 位) + 页表索引(10 位) + 页内偏移(12 位)**；CR3 指向页目录基址，逐级查表得到物理页帧号，拼上偏移。

**TLB**：页表项的硬件缓存，命中则免去多次内存访问；进程切换可能需刷新（ASID 可减少刷新）。
</details>

### 40. 缺页异常和段错误的区别？
<details><summary>📝 点开看答案</summary>

- **缺页异常（Page Fault）**：访问的虚拟地址**合法但页未映射/不在内存**（如首次访问 malloc 的内存、被换出）→ 内核补映射或换入，进程继续。是**正常机制**。
- **段错误（SIGSEGV）**：访问**非法地址**（空指针、越界、无权限）→ 内核发信号，进程终止。
</details>

### 41. 页面置换算法？什么是抖动？
<details><summary>📝 点开看答案</summary>

FIFO（简单但有 Belady 异常）、LRU（最近最少使用，效果好）、LFU、Clock（近似 LRU）。
**抖动（thrashing）**：内存严重不足，频繁换入换出，CPU 大部分时间在等 I/O，吞吐骤降。
</details>

### 42. 进程调度算法有哪些？
<details><summary>📝 点开看答案</summary>

FCFS（先来先服务）、SJF（短作业优先，可能饿死长作业）、优先级调度、时间片轮转 RR、多级反馈队列（Linux CFS 的思想来源之一）。
抢占式 vs 非抢占式：能否在运行中被打断。
Linux 实际用 **CFS**（按虚拟运行时间红黑树选最左）。
</details>

### 43. 什么是上下文切换？开销在哪？
<details><summary>📝 点开看答案</summary>

保存当前任务 CPU 寄存器/PC/栈指针，恢复下一个任务的状态。
开销：①寄存器保存恢复；②**页表切换导致 TLB 失效**；③CPU 缓存变冷；④内核调度开销。所以线程切换比进程便宜。
</details>

### 44. `fork()` 与短路表达式，创建几个进程？
<details><summary>📝 点开看答案</summary>

关键：**父进程和子进程都会继续执行后面的表达式**，且短路规则各自独立判断。

例：`if (fork() || fork()) { }`
- 父进程：第一个 fork 返回 >0（真）→ 短路，不再 fork；
- 子进程：第一个 fork 返回 0（假）→ 执行第二个 fork → 又创建一个。
**共 3 个进程**（原父 + 子 + 孙）。

方法：画进程树，每个 fork 分叉一次，注意短路。
</details>

### 45. 32 位系统下各类型字节数？
<details><summary>📝 点开看答案</summary>

char 1、short 2、int 4、long 4（32 位）、long long 8、float 4、double 8、**指针 4**。
64 位 Linux：long 8、指针 8（int 仍 4）。嵌入式答题先问"多少位平台"。
</details>

### 46. `/proc`、`/sys`、`/dev` 的区别？
<details><summary>📝 点开看答案</summary>

都是内核导出的**虚拟文件系统**，不在磁盘：
- `/dev`：设备节点（open/read/write 操作硬件）
- `/proc`：进程与内核状态（`/proc/cpuinfo`、`/proc/bus/input/devices`）
- `/sys`：设备与驱动的层次化视图（`/sys/class/gpio`、`/sys/class/leds`）
</details>

### 47. 怎么判断大端小端？网络字节序？
<details><summary>📝 点开看答案</summary>

```c
int x = 1;
char c = *(char *)&x;   // 1=小端，0=大端
```
或 union 判断。**网络字节序 = 大端**；转换函数 `htons/htonl/ntohs/ntohl`。
</details>

### 48. 文件描述符是什么？0/1/2？
<details><summary>📝 点开看答案</summary>

进程打开文件后内核返回的**非负整数索引**，指向进程的文件表项。
0=标准输入、1=标准输出、2=标准错误。上限受 `ulimit -n` 限制。
</details>

### 49. `fopen` 的 `r/w/a/+` 组合？
<details><summary>📝 点开看答案</summary>

`r` 只读（不存在则失败）、`w` 只写（清空/创建）、`a` 追加（创建）、`r+` 读写（不清空）、`w+` 读写（清空）、`a+` 读+追加。
加 `b` 二进制模式（Windows 下换行不转换）。
</details>

### 50. `GFP_KERNEL` 和 `GFP_ATOMIC` 的区别？
<details><summary>📝 点开看答案</summary>

- `GFP_KERNEL`：可**睡眠等待**内存，用于进程上下文。
- `GFP_ATOMIC`：**不睡眠**，用于中断上下文/持锁时；内存紧张时更容易失败。
- 口诀：能睡用 KERNEL，不能睡用 ATOMIC。
</details>

### 51. FreeRTOS 任务切换原理？
<details><summary>📝 点开看答案</summary>

每个任务有独立栈和 TCB（任务控制块）。切换时：保存当前任务寄存器到其栈 → 更新 TCB 栈指针 → 从最高优先级就绪任务恢复寄存器。
ARM Cortex-M 用 **PendSV 异常**做上下文切换（最低优先级，保证原子），SysTick 提供时基。
</details>

### 52. init 进程 PID 是多少？负责什么？
<details><summary>📝 点开看答案</summary>

**PID = 1**。内核启动后第一个用户态进程，负责启动系统服务、收养孤儿进程（现代发行版是 systemd）。它挂了系统就崩。
</details>

### 53. Bootloader 到内核启动各阶段做什么？
<details><summary>📝 点开看答案</summary>

BootROM → 一级引导（SPL，初始化 DDR）→ U-Boot（初始化串口/存储/网络，加载内核与 dtb 到内存，设置启动参数 bootargs，跳转内核）→ 内核解压/自解压 → 初始化内存管理/调度/驱动 → 挂载 rootfs → 执行 init。
</details>

### 54. ### 文件 I/O 和标准 I/O 的区别？（高频）
<details><summary>📝 点开看答案</summary>

| | 文件 I/O（低级 I/O） | 标准 I/O（高级 I/O） |
|---|---|---|
| 层次 | 系统调用，直接操作**文件描述符**（int） | C 库封装，操作 **FILE\* 流** |
| 缓冲 | **无缓冲**，每次直接进内核 | **带缓冲**，合并系统调用 |
| 函数 | open/read/write/close/lseek | fopen/fread/fwrite/fgets/printf |
| 可移植性 | POSIX | C 标准（跨平台） |

关系：标准 I/O 是文件 I/O 的封装，每个 FILE 流内部对应一个 fd。频繁小块读写用标准 I/O 快（缓冲合并）；要精确控制（设备、非阻塞）用文件 I/O。
</details>

### 55. ### open 的常用标志位有哪些？
<details><summary>📝 点开看答案</summary>

`O_RDONLY` 只读 / `O_WRONLY` 只写 / `O_RDWR` 读写（三选一）；
`O_CREAT` 不存在则创建（需第三参权限如 0644）；`O_APPEND` 追加写；`O_TRUNC` 打开即清空；
`O_EXCL`（配 O_CREAT：已存在则报错）；`O_NONBLOCK` 非阻塞；`O_SYNC` 同步写。

返回：成功非负 fd；失败 -1 并设 errno。
</details>

### 56. ### exit() 和 _exit() 的区别？
<details><summary>📝 点开看答案</summary>

- `exit()`：标准库函数，退出前**执行清理**——刷新 stdio 缓冲区、关闭流、调 atexit 函数，再进内核。
- `_exit()`：**直接系统调用进内核**，不刷新缓冲、不清理。

用法：一般用 exit()；**fork 后的子进程常用 _exit()**——防止把从父进程复制来的缓冲区也刷新一遍造成输出重复。
</details>

### 57. ### fork() 和 vfork() 的区别？
<details><summary>📝 点开看答案</summary>

| | fork | vfork |
|---|---|---|
| 地址空间 | 子进程**独立**（写时复制） | 与父进程**共享**地址空间 |
| 执行顺序 | 父子顺序不确定 | **保证子进程先运行**，直到它调 exec 或 exit |

vfork 的设计目的是紧跟 exec 执行新程序（省去复制地址空间）；有写时复制后 vfork 已少用。
</details>

### 58. ### 无名管道和有名管道的区别？
<details><summary>📝 点开看答案</summary>

- **无名管道 pipe()**：单向字节流、匿名（不在文件系统）、只能用于**有亲缘关系**的进程（fork 共享 fd）。双向要建两根管道。
- **有名管道 mkfifo()**：有文件系统路径名，**任意进程**间可用，打开方式同文件。
</details>

### 59. ### 消息队列、共享内存、信号量的 API 步骤？（System V）
<details><summary>📝 点开看答案</summary>

三者都用 `ftok()` 生成 IPC key。

**消息队列**（有格式消息）：`msgget` 创建 → `msgsnd` 发 → `msgrcv` 收 → `msgctl` 删。
缺点：缓冲区在**内核空间**，收发要多次用户态/内核态切换，大数据量开销大。

**共享内存**（最快，零拷贝）：`shmget` 创建 → `shmat` 映射 → 直接读写 → `shmdt` 解除 → `shmctl` 删。需配信号量同步。

**信号量**（PV 同步）：`semget` 创建 → `semctl` 初始化 → `semop` P（等）/V（放） → `semctl` 删。
</details>

### 60. ### 读写锁是什么？什么场景用？
<details><summary>📝 点开看答案</summary>

读锁**共享**：多个线程可同时持读锁；写锁**互斥**：只允许一个写者，且写者持锁期间不许任何读者。

适用：**读多写少**（配置表、缓存）。写频繁时读者会饿死，需注意。
</details>

### 61. ### TCP 和 UDP 的区别？各自适用场景？
<details><summary>📝 点开看答案</summary>

1. TCP **面向连接**（三次握手），UDP 无连接
2. TCP 面向**字节流**，UDP 面向**数据报**
3. TCP 可靠（不丢不乱序），UDP 尽力而为
4. TCP 有流量/拥塞控制；UDP 开销小延迟低

场景：TCP——文件传输、HTTP、固件升级（不能丢）；UDP——语音视频（丢帧卡一下没关系）、DNS、广播组播、游戏。
</details>

### 62. ### 线程切换需要保存哪些上下文？SP、PC、EAX 是干什么的？
<details><summary>📝 点开看答案</summary>

保存：线程 id、状态、堆栈、寄存器组。其中：
- **SP**：堆栈指针，指向当前栈顶
- **PC**：程序计数器，存**下一条要执行的指令**地址
- **EAX**：累加寄存器，加法/乘法缺省寄存器，也存函数返回值
</details>

# 第三级 ★★★ 驱动内核 + 网络编程 + IO 模型（34 题）

### 63. 字符设备注册完整流程？
<details><summary>📝 点开看答案</summary>

```c
alloc_chrdev_region(&dev, 0, 1, "name");  // 申请设备号
cdev_init(&cdev, &fops);                  // 绑定 file_operations
cdev_add(&cdev, dev, 1);                  // 加入内核
class_create(THIS_MODULE, "cls");         // 创建设备类
device_create(cls, NULL, dev, NULL, "name"); // 生成 /dev/name
```
卸载逆序：device_destroy → class_destroy → cdev_del → unregister_chrdev_region。
</details>

### 64. 设备、驱动、总线怎么匹配？优先级？
<details><summary>📝 点开看答案</summary>

设备与驱动注册到总线（platform/i2c/spi），总线负责匹配：
**of_match_table（设备树 compatible）> id_table > name 字符串**。
匹配成功调用驱动的 `probe()`；失败可返回 `-EPROBE_DEFER` 等待依赖。
</details>

### 65. 设备树 compatible 怎么工作？probe 何时调用？
<details><summary>📝 点开看答案</summary>

内核遍历设备树节点，用节点的 `compatible` 与各驱动 `of_match_table` 中的字符串**逐字比对**；匹配则调用该驱动的 probe。
probe 时机：①设备先注册、驱动后注册 → 驱动注册时匹配；②驱动先注册、设备后注册（设备树展开）→ 设备注册时匹配。
</details>

### 66. probe 成功但用户态 `open` 返回 `-ENODEV`，怎么查？
<details><summary>📝 点开看答案</summary>

分层查：①`/dev` 节点是否存在、主次设备号是否对（`ls -l /dev/xxx`）；②`/proc/devices` 里有没有注册；③open 实现里是否检查了硬件状态/引用计数返回 -ENODEV；④权限/udev 规则；⑤dmesg 有无报错。
常见：只 cdev_add 没 device_create → 没有 /dev 节点；或用 mknod 建错设备号。
</details>

### 67. 中断处理函数里为什么不能睡眠？
<details><summary>📝 点开看答案</summary>

中断上下文**不属于任何进程**：睡眠需要"挂起当前任务等唤醒"，但这里没有可挂起的任务；且中断要尽快返回，否则同一中断被屏蔽、系统卡死。所以不能调用可能睡眠的函数（mutex、kmalloc(GFP_KERNEL)、copy_to_user 等）。
</details>

### 68. 中断上下半部机制？tasklet 和 workqueue 区别？
<details><summary>📝 点开看答案</summary>

上半部：紧急、极短（应答硬件、清标志、记时间）。
下半部：延后处理耗时工作。
- **softirq**：静态注册、性能最高、可并发（网络收包）
- **tasklet**：基于 softirq，同类不并发，**不能睡眠**
- **workqueue**：进程上下文，**可以睡眠**，适合 I2C/SPI 读写等可能阻塞的操作
</details>

### 69. 自旋锁和互斥锁的区别？怎么选？
<details><summary>📝 点开看答案</summary>

| | 自旋锁 spinlock | 互斥锁 mutex |
|---|---|---|
| 拿不到锁 | 原地忙等（不睡眠） | 睡眠让出 CPU |
| 适用 | 中断上下文、极短临界区、多核 | 进程上下文、较长临界区 |
| 开销 | 浪费 CPU，但无切换开销 | 有上下文切换开销 |

规则：**中断上下文只能用自旋锁**；临界区里不能睡眠。
</details>

### 70. 中断上下文能用信号量吗？
<details><summary>📝 点开看答案</summary>

**不能**用会睡眠的 `down()`/`mutex_lock()`（中断不能睡眠）。
只能用**非阻塞**版本：`down_trylock()`/`mutex_trylock()`，失败就返回；或改用自旋锁/原子操作/completion。
</details>

### 71. `kmalloc` 和 `vmalloc` 区别？伙伴系统和 slab？
<details><summary>📝 点开看答案</summary>

- `kmalloc`：物理**连续**，大小有限（通常 ≤128KB），速度快，适合 DMA/硬件。
- `vmalloc`：虚拟**连续**、物理可不连续，适合大块内存，但访问慢（多一次页表转换），不能用于 DMA。
- **伙伴系统**：以 2 的幂管理物理页帧，解决外部碎片。
- **slab/slub**：在伙伴系统之上做小对象缓存（kmalloc 的底层），减少碎片、加速分配。
</details>

### 72. `copy_to_user` 和 `memcpy` 区别？`ioremap` 作用？
<details><summary>📝 点开看答案</summary>

- `copy_to_user`：内核→用户空间拷贝，会**检查用户地址合法性**（access_ok），失败返回未拷贝字节数；不能直接用 memcpy（用户地址可能非法）。
- `ioremap`：把**物理寄存器地址映射成内核虚拟地址**，之后用 readl/writel 访问；用完 `iounmap`。
</details>

### 73. `mmap` 为什么能提高驱动传输效率？
<details><summary>📝 点开看答案</summary>

普通 read：数据 硬件→内核缓冲→用户缓冲，两次拷贝。
`mmap`：把设备的物理内存/内核缓冲**直接映射到用户地址空间**，用户读写即访问硬件缓冲，**零拷贝**，适合 framebuffer、摄像头、大块数据。
</details>

### 74. DMA 一致性内存 vs 流式内存？cache 一致性？
<details><summary>📝 点开看答案</summary>

- **一致性 DMA（coherent）**：`dma_alloc_coherent`，CPU 与设备看到一致，通常关闭该区域 cache，适合长期双向共享（描述符环）。
- **流式 DMA（streaming）**：`dma_map_single`，用完 `dma_unmap_single`；需要 `dma_sync_*` 在 CPU 与设备间同步 cache。
- 原因：CPU 写的数据可能还在 cache 没进内存，设备读不到 → 必须 flush/invalidate。
</details>

### 75. platform 总线模型是什么？为什么需要？
<details><summary>📝 点开看答案</summary>

SoC 内部外设（UART/I2C 控制器等）没有可枚举的总线（不像 USB），内核造了虚拟的 **platform 总线**：设备（设备树节点展开）与驱动各自注册，按 compatible/name 匹配后 probe。好处：统一设备模型、支持设备树、电源管理。
</details>

### 76. I2C 和 SPI 的区别？NACK 怎么排查？
<details><summary>📝 点开看答案</summary>

| | I2C | SPI |
|---|---|---|
| 线 | 2（SCL/SDA）+ 地址 | 4（SCK/MOSI/MISO/CS） |
| 设备选择 | 地址 | 片选 |
| 速度 | 100k/400k/1M | 几 M~几十 M |
| 多主 | 支持 | 一般单主 |

NACK 排查：①地址对不对（7 位/8 位）②引脚复用与上拉 ③供电/复位 ④时序/速率 ⑤用示波器/逻辑分析仪看波形。
</details>

### 77. 内核 oops/panic 怎么定位？printk 等级？
<details><summary>📝 点开看答案</summary>

oops 日志里有：**PC 值、调用栈（Call trace）、模块名、寄存器**。用 `addr2line -e vmlinux 地址` 或 `gdb vmlinux` 定位到源码行；开 `CONFIG_DEBUG_INFO`、`kdump`/`pstore` 保存崩溃现场。
printk 等级 0–7：0 EMERG、1 ALERT、2 CRIT、3 ERR、4 WARNING、5 NOTICE、6 INFO、7 DEBUG；`printk(KERN_ERR "...")` 或 `pr_err()`。
</details>

### 78. `open`/`read` 一次系统调用的完整路径？
<details><summary>📝 点开看答案</summary>

用户 `open()` → glibc 封装 `syscall` → 陷入内核 `sys_open`/`do_sys_open` → 查路径得到 **inode** → 分配 **file** 结构 → 调用 inode 对应驱动的 `file_operations->open` → 返回 **fd**（进程 fd 表索引）。
`read(fd,...)` → 用 fd 找到 file → 调 `file->f_op->read` → 驱动 copy_to_user。
</details>

### 79. 字符设备从 inode 到 f_op 的链路？
<details><summary>📝 点开看答案</summary>

`/dev/xxx` 是字符设备节点，含**主/次设备号**；打开时内核用设备号在 **cdev 映射表**里找到注册的 `cdev`，取出其中的 `file_operations`，赋给新建的 `file->f_op`。之后 read/write/ioctl 都经 f_op 分发到驱动。
</details>

### 80. `volatile const` 组合用在哪？
<details><summary>📝 点开看答案</summary>

**只读硬件寄存器**：程序不应写它（const），但值会被硬件改变（volatile），每次都必须重新读。
例：`#define REG (*(volatile const uint32_t *)0x40000000)`。
</details>

### 81. platform 驱动与设备树怎么匹配？probe 何时调用？
<details><summary>📝 点开看答案</summary>

驱动里 `of_match_table` 列出 compatible 字符串；设备树节点 `compatible = "vendor,dev"` 与之匹配 → `platform_driver.probe` 被调用。probe 里用 `of_*` API 取寄存器地址、中断号、GPIO 等资源。
</details>

### 82. softirq / tasklet / workqueue 怎么选？
<details><summary>📝 点开看答案</summary>

- 极致性能、可并发、不需睡眠 → **softirq**（一般不用自己写）
- 短小、不需睡眠、同类串行 → **tasklet**
- 可能睡眠（I2C/SPI 读写、大内存分配）→ **workqueue**
口诀：能睡就 workqueue，不能睡就 tasklet。
</details>

### 83. 中断上下文里自旋锁和信号量怎么选？
<details><summary>📝 点开看答案</summary>

中断里只能 **spinlock**（或 spin_lock_irqsave 关中断防死锁）；信号量/mutex 会睡眠，禁止。若中断与进程共享数据：进程侧用 `spin_lock_irqsave`，中断侧用 `spin_lock`。
</details>

### 84. V4L2 + mmap 多缓冲采集流程？
<details><summary>📝 点开看答案</summary>

`open /dev/video0` → `VIDIOC_QUERYCAP` → `VIDIOC_S_FMT` 设格式 → `VIDIOC_REQBUFS` 申请 N 个缓冲 → 对每个 `VIDIOC_QUERYBUF` + `mmap` 映射到用户态 → `VIDIOC_QBUF` 入队 → `VIDIOC_STREAMON` → `poll/select` 等帧 → `VIDIOC_DQBUF` 取一帧 → 处理完 `QBUF` 还回队列。多缓冲避免采集与处理互相阻塞。
</details>

### 85. 生产者—消费者队列怎么实现？
<details><summary>📝 点开看答案</summary>

环形缓冲区 + 两个指针（读/写）+ 同步原语：
- 有界队列：用**信号量**（empty/full）或条件变量 + 互斥锁；
- 无锁：单生产者单消费者可用原子操作 + 内存屏障。
要点：队列满时生产者阻塞、空时消费者阻塞；避免忙等。
</details>

### 86. DMA-BUF 是什么？
<details><summary>📝 点开看答案</summary>

内核中**跨驱动共享 DMA 缓冲**的框架：一个驱动分配缓冲并导出 fd，其他驱动/用户态通过 fd 导入同一块物理内存，**零拷贝**。典型：摄像头采集 → 显示/编码器直接消费，不复制。配合 dma_fence 做同步。
</details>

### 87. Cache 一致性在 DMA 场景怎么处理？
<details><summary>📝 点开看答案</summary>

CPU 写的数据可能停在 cache：设备 DMA 读内存前要 **clean/flush**（写回）；设备 DMA 写内存后 CPU 读之前要 **invalidate**（丢弃旧 cache）。
接口：`dma_map_single/unmap_single`、`dma_sync_single_for_device/cpu`；或直接用 coherent 内存（关闭 cache）。
</details>

### 88. ### 中断上下文有哪四条注意事项？
<details><summary>📝 点开看答案</summary>

1. **不能睡眠/放弃 CPU**——进中断前内核关了调度，一睡系统就死
2. **不能获取信号量**（拿不到就睡眠）；mutex 也不行
3. **不能执行耗时任务**——快进快出，耗时活放下半部
4. **不能访问用户空间虚拟地址**——中断在内核空间运行

能用的：自旋锁（短临界区）、`GFP_ATOMIC` 分配、trylock。
</details>

### 89. ### TCP 怎么保证可靠性？
<details><summary>📝 点开看答案</summary>

1. **序列号 + 确认应答 + 超时重传**：接收方回 ACK 指明下一个要收的序号；超时（约 2×RTT+偏差）未确认就重传
2. **滑动窗口**：窗口内无需逐个等确认，连续发送提高吞吐
3. **快速重传**：收到 **3 个重复 ACK** 立即重传对应报文
4. **数据排序**：序列号支持乱序重排
5. **拥塞控制四算法**：慢启动、拥塞避免、快速重传、快速恢复
6. 校验和：校验失败丢弃
</details>

### 90. ### 详细说说 TCP 三次握手？为什么是三次？
<details><summary>📝 点开看答案</summary>

过程（客户端初始序号 x，服务器 y）：
1. 客户端 → 服务器：**SYN=1，Seq=x**
2. 服务器 → 客户端：**SYN=1，ACK=1，Seq=y，Ack=x+1**
3. 客户端 → 服务器：**ACK=1，Seq=x+1，Ack=y+1**

**为什么三次**：
①确认**双方收发能力都正常**——少了第三次，服务器无法确认"客户端能收到我的消息"；
②防止**历史失效的连接请求**突然到达——两次握手下服务器会误建立无效连接浪费资源。

类比：喂听得到吗？→ 听得到你呢？→ 我也听到了，开聊。
</details>

### 91. ### 详细说说四次挥手？为什么是四次？二三次能合并吗？
<details><summary>📝 点开看答案</summary>

过程（客户端 Seq=u，服务器 Seq=v）：
1. 客户端 → 服务器：**FIN=1，Seq=u**（我说完了）
2. 服务器 → 客户端：**ACK=1，Ack=u+1**（知道了，但我可能还有话）
3. 服务器 → 客户端：**FIN=1，Seq=v+1**（我也说完了）
4. 客户端 → 服务器：**ACK=1，Ack=v+2**（拜拜，等 2MSL 关闭）

**为什么四次**：TCP **全双工**，两个方向分别关闭——客户端说完 ≠ 服务器说完。
**二三次通常不合并**：服务器收到 FIN 时可能还有数据没发完，要先 ACK，发完数据才发自己的 FIN，中间有时间差（半关闭状态）。
</details>

### 92. ### 基于 TCP 的 socket 编程流程？UDP 呢？
<details><summary>📝 点开看答案</summary>

**TCP 服务端**：`socket` → `bind`（绑 IP+端口）→ `listen`（监听+最大连接数）→ `accept`（阻塞等连接，返回新 fd）→ `send/recv`（或 write/read）→ `close`。
**TCP 客户端**：`socket` → `connect` → `send/recv` → `close`。

**UDP**（无连接，简单）：服务端 `socket → bind → recvfrom/sendto → close`；客户端 `socket → sendto/recvfrom → close`。
</details>

### 93. ### HTTP 和 HTTPS 的区别？
<details><summary>📝 点开看答案</summary>

1. HTTP **明文**传输；HTTPS 经 **TLS 加密**
2. HTTPS 在 TCP 握手后还要 **SSL/TLS 握手**协商对称密钥
3. HTTPS 需要服务端**证书**（CA 签发）
4. 端口：HTTP **80**，HTTPS **443**

代价：握手延迟 + 加解密耗 CPU。嵌入式上云（AI 语音、数据上传）一般走 HTTPS/TLS。
</details>

### 94. ### Linux 下有哪五种 IO 模型？同步和异步的区别？
<details><summary>📝 点开看答案</summary>

五种：**阻塞 IO、非阻塞 IO、IO 多路复用（select/poll/epoll）、信号驱动 IO（SIGIO）、异步 IO**。前四种属**同步 IO**。

一个完整 IO 两步：①等数据就绪（进内核缓冲）②数据从内核拷到用户缓冲。
- 同步：①②都要应用参与/等待
- 异步：发起即返回，内核就绪+拷贝完成后回调通知（②也由内核完成）

非阻塞 IO：`open` 加 `O_NONBLOCK`，read 无数据立即返回错误（轮询）。
阻塞 IO：read 无数据时进程在内核态休眠，数据到了被唤醒。
</details>

### 95. ### select、poll、epoll 的区别？（高频）
<details><summary>📝 点开看答案</summary>

| | select | poll | epoll |
|---|---|---|---|
| 数据结构 | fd_set 位图 | pollfd 数组 | **红黑树 + 就绪链表** |
| fd 上限 | **1024** | 无硬限制 | 无硬限制 |
| 每次调用开销 | 全量拷贝进内核 + 遍历全部 fd | 同左 | epoll_ctl 管理一次；wait **只返回就绪的** |
| 返回方式 | 改 fd_set，应用遍历 | 改 revents，遍历 | 直接给就绪列表 O(1) |
| 触发模式 | 仅 LT | LT/ET | LT/ET |

**怎么选**：连接少且活跃 → select；跨平台 → poll；**连接多、大量长连接 → epoll**。

epoll 两大优化：①红黑树管理 fd，避免每次全量拷贝；②事件回调，就绪的才进就绪链表，无需遍历全部。
</details>

### 96. ### 信号驱动 IO（异步通知）怎么用？
<details><summary>📝 点开看答案</summary>

预先告诉内核：fd 有事件就发 **SIGIO** 信号。三步：
1. `signal(SIGIO, handler)` 注册信号处理函数
2. `fcntl(fd, F_SETOWN, getpid())` 指定接收信号的进程
3. `fcntl(fd, F_SETFL, flags | FASYNC)` 开启异步通知

之后数据就绪时内核发 SIGIO，在 handler 里处理。适合"数据到达时间不确定、不想阻塞也不想轮询"的场景。驱动侧需实现 fasync 接口。
</details>

### 100. 手机连蓝牙音箱卡顿，怎么定位和解决？
