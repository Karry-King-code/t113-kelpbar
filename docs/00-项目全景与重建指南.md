## 2.2 全部外设引脚表（★ 最重要的表）

| 外设 | 接口/总线 | 引脚 | 关键参数 | 备注 |
|---|---|---|---|---|
| **调试串口** | UART3 | **PB6(TX) / PB7(RX)** | 115200-8N1 | 引脚功能号 **7**；座子 U24 |
| **LED1** | GPIO | **PD11** | 高电平点亮 | 全局号 107 |
| **按键 BTN1** | GPIO | **PD10** | 按下为低 | 全局号 106；键值 115 |
| **触摸** | I2C(TWI1) | **SCL=PE0 / SDA=PE1** | 地址 **0x5D**，400kHz | INT=PE5，RST=PE4；设备 `/dev/input/event5` |
| **屏幕** | MIPI DSI | 4 lane | **720×1424**，驱动 IC **FL7707N** | 座子 FPC2（32 脚）；fb0 32bpp 双缓冲 |
| **功放** | GPIO | **PB2**（全局 34） | **低电平=工作**（SHDN 高=关断） | LM4871；喇叭座 CN2 |
| **麦克风** | 模拟 | MIC3 差分输入 | 驻极体 GMI4015P，偏置 R148 | ADC3 Gain=19 |
| **WiFi** | SDIO | — | Realtek **RTL8723DS**，ID `024c:d723` | 驱动 rtl8723ds.ko |
| **蓝牙** | UART1 | **PG6(TX)/PG7(RX)** | H5 协议，115200 | RTS/CTS(PG8/9) 板上未引出 |

## 2.3 三个必须记住的硬件坑

1. **PB6 的 uart3 功能号是 7**（不是 3）——查内核 C 表 `PINCTRL_PIN(B, 6)` 得到 `SUNXI_FUNCTION(0x7,"uart3")`。交叉验证：PG8 的 uart3 是 0x5，与官方评估板配置 `<5>` 吻合。
2. **LM4871 的 SHUTDOWN 脚高电平=关断**（TI 手册 p11 原文），低电平才工作，板上 100kΩ 下拉让它默认工作——拉高会把功放关掉（此坑耗了两天）。
3. **GT9xx 触摸在 TWI1 不在 TWI2**——评估板方案是 twi2，直接抄会走一大圈弯路。

# 4. 九个关卡全记录（核心结论版）

> 每关格式：**目标 → 硬件事实 → 改了什么文件、为什么 → 关键坑 → 验证方法**。逐条命令版在同目录各关卡 README（01-serial ~ 09-lvgl）。

## 4.1 调试串口（UART3 / PB6,PB7）

**改三个文件**（分别管三个启动阶段，缺一不可）：
| 文件 | 管什么 | 改什么 |
|---|---|---|
| `openwrt/env.cfg` | 内核 earlycon（驱动加载前的最早打印） | 串口寄存器地址 `0x05000000` → **`0x02500C00`** |
| `sys_config.fex` | U-Boot 阶段（全志私有 FEX 格式，**不是设备树**） | `port:PG08<5>` → `port:PB06<7>`，`PG09<5>` → `PB07<7>` |
| `linux-5.4/board.dts` | 内核阶段（设备树） | `pins = "PG8","PG9"` → `"PB6","PB7"`（**两处，sed 要加 g**） |

**关键坑**：
- **查看 vs 修改是两个地方**：查引脚字典去 `~/T113-Tina5.0-V1.2/kernel/linux-5.4/drivers/pinctrl/sunxi/pinctrl-sun8iw20.c`（只查不改）；要改的文件在 `device/config/chips/t113/configs/evb1_auto_nand/`
- **字典的搜法是宏写法**：`grep -n -A8 'PINCTRL_PIN(B, 6)' 文件`（搜 `"PB6"` 搜不到）
- **软链接陷阱**：`sed -i` 改软链接会销毁链接生成普通文件——验证读新文件、编译读真身，"验证和编译读的是两个文件"。改 `linux-5.4/board.dts` 真身。
- **内核精确卡死**（16 秒看门狗复位、每次卡同一行）：开 `initcall_debug`，最后只有 `calling` 没有 `returned` 的驱动就是凶手；本次是空总线 twi3 让 `-517`（EPROBE_DEFER 补考机制）死等 → twi3 设 disabled。

**验证**：串口见 `HELLO! BOOT0` → `U-Boot 2018.07` → `Linux version 5.4.61` → `Please press Enter` → shell。

## 4.2 LED + 按键（PD11 / PD10）

**改两个文件**（分工：config 开功能，dts 接硬件）：
- `config-5.4` 追加：`CONFIG_NEW_LEDS`、`CONFIG_LEDS_CLASS`、`CONFIG_LEDS_GPIO`、`CONFIG_GPIO_SYSFS`、`CONFIG_KEYBOARD_GPIO`（+历史上多写的 `CONFIG_GPIO_KEYS`）
- `board.dts` 追加 `leds`（compatible="gpio-leds"，`gpios=<&pio 3 11 GPIO_ACTIVE_HIGH>`）和 `gpio-keys`（compatible="gpio-keys"，`<&pio 3 10 GPIO_ACTIVE_LOW>`，`linux,code=115`）两个节点

**★ 源码查证的重要发现**：`CONFIG_GPIO_KEYS` **在内核源码里不存在**（`grep 'config GPIO_KEYS' drivers/input/` 零输出），写入配置被静默丢弃。按键真正的开关只有 **`CONFIG_KEYBOARD_GPIO`**（Kconfig 里只依赖 GPIOLIB）。当年"6 个开关"配方中这个是幽灵符号。通用方法：`grep -A6 'config 开关名' drivers/.../Kconfig` 查真假和依赖。

**关键坑**：按键设备名是驱动名 **`gpio-keys`**，不是 label 里的 `kelpbar:btn1`——搜 kelpbar 零输出会误判。板上 `/dev/input/event2` 是评估板残留的电阻触摸在空抖，**认设备要认 Name，不要认"谁在动"**。

**验证**：`echo 255 > /sys/class/leds/kelpbar:led1/brightness` 灯亮；`cat /proc/bus/input/devices | grep -A4 gpio-keys` 见 event4；`cat /dev/input/event4` 按按键刷事件流。

## 4.3 触摸（GT9xx @ TWI1 / PE0,PE1 / 0x5D）

**全部改动在 `board.dts`（三次手术）**：
1. **删幽灵节点**：驱动用 `of_find_node_by_name(NULL,"ctp")` 找"全树第一个叫 ctp 的节点"，twi0 下旧的 `ctp@14` 排在前面挡道 → 报 `ctp is not used`。删掉，`grep -c "ctp@" board.dts` 必须 = 1
2. **改引脚**：`twi1_pins_a/b` 的 `pins = "PE14","PE15"` → **`"PE0","PE1"`**（板级默认抄评估板；本板原理图 TP_SCL/TP_SDA 在 PE0/PE1；查字典 `PINCTRL_PIN(E,0)` 得 `0x4="twi1"`）
3. **关 twi2**：`status="okay"` → `"disabled"`（本板触摸不在 twi2；且 twi2 与 usb_id_gpio 抢 PE12）

**认知三金句**：**枚举 ≠ 应答**（dts 里声明了节点 ≠ 芯片真的应答）；**控制器对 ≠ 线对**（总线号开了 ≠ 引脚对）；**能力 ≠ 接线**（芯片支持某功能 ≠ 板上就接在那）。
**坑**：驱动日志里"请把 sys_config.fex 的 ctp_used 设为 1"是**过时提示**，别信，配置早就在设备树里了。

**验证**：`cat /proc/bus/input/devices | grep -A4 gt9xx` 见 `event5`；`hexdump -C /dev/input/event5` 手按屏幕刷坐标（`03 00 35`=X，`03 00 36`=Y）。

## 4.4 显示（FL7707N MIPI 4lane 720×1424）

**这关的特殊性**：屏的引脚、驱动、设备树节点在板级配置里**本来就已经对了**（`lcd_used=1`、`lcd_driver_name="fl7707n_mipi"`、`lcd_dsi_lane=4`、`lcd_x=720/lcd_y=1424`、`CONFIG_DISP2_SUNXI=y`）——**要先查证它们，再找真正的问题**。

**黑屏破案六步**：
1. 日志无 `lcd_open_flow` → 内核没初始化屏
2. 日志有 `smooth display` → U-Boot 抢先开屏，内核礼让跳过
3. 改 `lcd_used=0` 无效 → **它不是开关**（只做分辨率校验，名字骗人）
4. 真凶：U-Boot 编译宏 **`CONFIG_BOOT_GUI`**（无条件开屏）
5. 关掉重编，镜像小 32KB = 代码真被裁掉的物证
6. fb 尺寸 1024×600 ≠ 面板 720×1424 → 改 board.dts 的 `fb0_width/fb0_height`

**改动**：
- U-Boot：`~/T113-Tina5.0-V1.2/brandy/brandy-2.0/u-boot-2018/configs/sun8iw20p1_auto_defconfig` 和同目录 `.config`（**两个都改**：defconfig 管永久、.config 管这次编译）
- 内核：`board.dts` 的 `disp@5000000` 节点 fb 尺寸

**彩条持久化**：`echo 1 > /sys/class/disp/disp/attr/colorbar` 改的是内核内存变量，断电丢 → 写 `/etc/rc.local`（板上一份 + SDK 的 `base-files/etc/rc.local` 一份），验证 `ls /overlay/upper/etc/rc.local`。

## 4.5 喇叭（LM4871 + CN2）

**链路**：音乐文件 → aplay → 内核声卡 audiocodec → HPOUT → LM4871 功放 → CN2 → 喇叭。

**★ 核心坑：SHDN 极性**。TI LM4871 手册 p11："logic high = shutdown"——**高电平关断，低电平工作**。板上 R138 100kΩ 下拉，默认就是工作；当初"使能脚拉高"把功放关了，无声两天。**带 SHDN/EN 的引脚必须查数据手册。**

**命令**：
```sh
echo 34 > /sys/class/gpio/export; echo out > /sys/class/gpio/gpio34/direction; echo 0 > /sys/class/gpio/gpio34/value
amixer cset name='HPOUT Switch' 1; amixer cset name='HPOUT Gain' 7
amixer cset name='DACL Volume' 200; amixer cset name='DACR Volume' 200
aplay /root/audio/test_440.wav      # MP3 用 madplay（固件需含该包）
```
**/sys 是什么**：内核把设备和驱动状态"投影"成虚拟文件（sysfs），不是磁盘文件、也不是设备树。设备树是"因"（静态说明书），/sys 是"果"（驱动生成的运行时控制面板）。**没有驱动认领节点，就没有 /sys 操作文件**——这就是"孤儿节点"的实质。
**全局编号换算**：全局号 = 组号×32 + 组内脚号（A=0,B=1,C=2,D=3）。PB2=1×32+2=34；PD11=3×32+11=107。

## 4.6 麦克风（板载驻极体 GMI4015P）

**零配置**：MIC3 差分输入 + rc.local 出厂预设（MIC3 Input Select=1 / Switch=on / ADC3 Gain=19）恰好匹配本板，直接录。
```sh
arecord -f S16_LE -r 16000 -c 1 -d 5 /root/audio/rec.wav
aplay /root/audio/rec.wav
```
**★ 方法论：命令没报错 ≠ 功能正常**。把 wav 拉回电脑算峰值/RMS：全零=没录到；实测峰值 32767、RMS 393 = 真实信号。
**坑**：录音与放音共用声卡，音乐循环在跑会 `Device or resource busy`——杀播放器还要杀 while-true 循环 shell。

## 4.7 WiFi（RTL8723DS 换驱动）

**诊断**：芯片活着（SDIO ID `024c:d723`）+ 驱动装错（固件里是 XR829，日志 `[SBUS_ERR] sdio probe timeout`）→ 换 rtl8723ds。

**三层配置（必背分工）**：
| 文件 | 管什么 | 改什么 |
|---|---|---|
| `linux-5.4/config-5.4` | 内核编什么 | `CONFIG_RTL8723DS=m`（不能 =y：自带加密库与内核重名） |
| `openwrt/openwrt/target/linux/t113-common/modules.mk` | .ko 打进哪个包（"菜谱"） | 新增 `KernelPackage/net-8723ds`（FILES + AUTOLOAD） |
| `openwrt/target/t113/t113-evb1_auto_nand/defconfig` | 系统装哪些包（"点菜单"） | `CONFIG_PACKAGE_kmod-net-8723ds=y` |
| `board.dts` | 硬件 | `rfkill@0` status → `okay`（父节点关了子节点不加载） |

**关键坑**：
- 裸 .ko 不进系统——OpenWrt 只装"清单上选了的包"
- **中文 SSID**：手机广播"名称1"实际只发出 "1"，按 `wifi -s`/`wpa_cli scan_results` 的真实名字连
- wpa_cli 必须加 `-p /etc/wifi/wpa_supplicant/sockets`

**验证三层**：`wpa_state=COMPLETED`（链路）→ 拿到 IP（网络）→ `ping 223.5.5.5` 通（传输）。

## 4.8 蓝牙（全书最难：15 个问题、五层洋葱 + 带宽战）

**启动五条件**（固化在 `/etc/bt_up.sh`）：
1. **删 `/lib/firmware/rtlbt/rtl8723d_config`**（原版要求 4.9M 波特+硬件流控，板子做不到）
2. **芯片冷启动**（断电 15 秒；假死唯一解法；手机连着时绝不能 kill 蓝牙进程）
3. `btmgmt ssp on` + `btmgmt io-cap 3`（NoInputNoOutput 免确认）
4. `btmgmt bondable on`
5. `hciconfig hci0 class 0x240404`（音频类；class=0 会被搜索隐藏）

**核心概念：配对 ≠ 连接**。配对=换密钥建立信任；连接=跑业务。业务要**注册 SDP 服务**：`sdptool add --channel=3 SP`（串口）、`sdptool add A2SNK`（音频）。SDP 记录在 bluetoothd 内存里，每次开机重注册。

**★ 全书最重要的机制：配对快照**。对端（手机/电脑）的 profile 列表是**配对那一刻**的 SDP 快照；板子事后补注册的服务对方不知道 → 必须**删配对重配**。固定顺序：先修好板子服务，再让对端重配。

**A2DP 五层坑**（每层都靠 btmon 抓包实锤）：
1. 缺配对应答员（agent）→ `Authentication attempt without agent` / `Access denied`；且 A2DP 必须鉴权而 rfcomm 不需要——这是"串口能连、音乐不能"的根源
2. agent 能力被 bluetoothctl 抢走（它启动会自动注册 KeyboardDisplay）→ 用 `--agent NoInputNoOutput` 启动参数 + 30 秒自愈
3. bluealsa 端点/SDP 记录丢失 → 重启 bluealsa，看 `Endpoint registered`
4. 配对快照机制（见上）
5. SDP 应答 5 字节空（BlueZ 5.54 + -C 的坑，A2DP 记录不自动生成）→ 手动 `sdptool add A2SNK`

**卡顿（带宽战）**：
- 实测：UART1 到达 **10.2 KB/s**（hciconfig RX bytes 8 秒差值），立体声 SBC 需 **~41 KB/s**——管道只有 1/4，数据饿死（不是接触问题：接触=杂音，饿死=整段断）
- 提速路线（改芯片波特率 1.5M）失败：编码正确但固件下载超时，每次失败芯片假死要断电
- **正路：改 bluealsa 源码让 sink 只广播单声道+bitpool**，`src/a2dp.c` 三行（去 const、channel_mode=MONO、max_bitpool=10）；bitpool12≈恰好顶满、**bitpool10≈8KB/s 留 20% 余量** → 流畅
- **验证纪律**：只认 btmon 里 AVDTP 协商的 `Maximum Bitpool`；ALSA hw_params 的 channels、RX 速率、"感觉变好了"都不作数（手机会缓存协商结果，改完板子要重启手机蓝牙）

**排查工具**：`btmon -w /tmp/x.btsnoop`（板上无 nohup，用 start-stop-daemon 后台化）+ PC 端 `parse_sdp.py` 解析（btmon 文字输出不显示 UUID）；`bluetoothctl` 排查期间禁用（会抢 agent）。

## 4.9 LVGL（无屏先行移植）

**关键决策：不用课程 app_sdk_v2（网盘 460MB），用 Tina SDK 自带的 lvgl-8**：
- 库：`platform/thirdparty/gui/lvgl-8/lvgl`（8.3.2）
- 移植层：同目录 `lv_drivers`（sunxifb 处理 fb0/双缓冲/尺寸自适应，evdev 处理触摸）
- 模板：`openwrt/package/thirdparty/gui/lvgl-8/lv_examples/src/`（main.c + lv_conf.h + lv_drv_conf.h + Makefile）
- 编译：`make CC=arm-openwrt-linux-gcc`（PATH + STAGING_DIR），**3 分钟、零下载、不重编固件**
- **唯一修改**：`lv_drv_conf.h` 的 `EVDEV_NAME` `/dev/input/event3` → **`/dev/input/event5`**

**无屏验证（云看屏）**：`cat /dev/fb0 > /tmp/fb.raw`（8,202,240B = 720×2848×4 双缓冲）→ adb pull → PIL `Image.frombytes('RGBA',(720,1424),data[:W*H*4],'raw','BGRA')` → PNG。实测 dump 出完整 widgets demo 画面。
**运行**：`start-stop-daemon -S -b -m -p /var/run/lvgl.pid -x /usr/bin/lv_examples -- 0`（0=widgets 1=music 2=benchmark 3=keypad 4=stress）
**六层证据**：进程存活 / fd 3→/dev/fb0 / fd 4→/dev/input/event5 / utime 增长 / fb0 dump 出画面 / `disp/attr/sys` 的 fps:51.5 + vsync 中断增长。
**换屏清单**：买屏确认 5 项（FL7707 / 720×1424 / MIPI 4lane / GT9 触摸 / 排线同规格）→ 烧现有固件 → 复核 fb 尺寸 → push lv_examples → 复核 event 号 → 启动。黑屏先发彩条区分是新屏适配还是 LVGL 问题。

# 6. 十条方法论（每条都有事故背书，面试必讲）

1. 敲命令前先看提示符——VM/Windows/板子三个终端能力不同
2. 配置和硬件对不上就改配置——**这就是移植**
3. 改 board.dts 前确认不是软链接；改完看 mtime
4. 板上写完文件必 `sync`；自启脚本 /etc 与 /root 双份 + 进 SDK
5. 内核开关加了没效果 = 依赖没满足或符号不存在（查 Kconfig）
6. **认设备要认名字，不要认"谁在动"**
7. **名字骗人**——配置是不是开关，去读解析它的代码（lcd_used 不是开关）
8. **命令没报错 ≠ 功能正常**——验证看数据
9. **对端的功能列表是配对那一刻的快照**——先修服务，再删配对重配
10. **出问题先算账再动手**（带宽、地址、时序），数字会告诉你方向

# 7. 关键调试技术（可复用的"兵器谱"）

| 场景 | 技术 | 命令/方法 |
|---|---|---|
| 看系统死在哪 | 串口日志 + initcall_debug | 最后只有 calling 没 returned 的驱动=凶手 |
| 看设备注册没 | `/proc/bus/input/devices` 按 Name 匹配 | 别信 event 号（会变） |
| 抓原始事件 | hexdump /dev/input/eventX | 16 字节：type/code/value；EV_SYN 分帧 |
| 看驱动/设备状态 | `/sys/class/...`、`/sys/kernel/debug/gpio` | debugfs 是终极真相 |
| 蓝牙抓包 | `btmon -w x.btsnoop` + PC 解析 | btmon 文字不显示 UUID；btsnoop 头无记录数，flags 低位是 PB 标志 |
| 测串口带宽 | `hciconfig` RX bytes 8 秒差值 | 10.2KB/s 就是这么测的 |
| 无屏看画面 | `cat /dev/fb0` + PIL BGRA 解码 | 720×1424×4 |
| 验证音频数据 | Python wave 读 peak/rms | 全零=假录 |
| 查内核符号真假 | `grep 'config XXX' Kconfig` | pinctrl 表搜 `PINCTRL_PIN(组,脚)` |
