# Ubuntu + T113 SDK 环境重建教程（给新电脑 / 给 AI 执行）

> **这份文档给谁**：换电脑后，需要重新搭建这套嵌入式 Linux 编译环境的人（或帮忙操作的 AI）。
> **目标**：从一台**空电脑**开始，装出能编译 T113 固件的完整环境。**又快又稳**，避免踩坑。
> **预计耗时**：2～3 小时（其中 SDK 拷贝/解压 40 分钟，首次编译 40 分钟，其余 40 分钟）。
> **已验证事实**（2026-10 实测）：Ubuntu **24.04.4 LTS** 可直接编译；宿主 gcc 13.3 + 交叉 gcc 8.3.0；SDK 占 39GB；12 核编译约 30-40 分钟。

---

## 给 AI 的执行说明（用户把这份文档交给你时）

> 用户在 Windows 电脑上重建环境。请你**按步骤一问一答地引导**：每步给出命令 → 让用户执行 → 检查输出 → 再进下一步。不要一次抛出全部命令，不要跳过验证。
> 关键约束：①SDK 存放路径**不能有中文、不能有空格** ②虚拟机磁盘**至少 150GB** ③内存**至少 12GB**（编译很吃内存）④所有 `sudo` 命令会要密码，提醒用户输入。
> 若某步失败，先查文末《常见错误对照表》。

# 0. 先选路线（30 秒决策）

| 你的情况 | 走哪条路 |
|---|---|
| 有原电脑导出的虚拟机备份（`.ova` 文件） | **最快**：VirtualBox → 导入 .ova → 直接跳到第 9 步验证。10 分钟搞定 |

| 电脑配置太低（<8 核 / <16G 内存 / 无 100G 空闲盘） | **不要装编译环境**。只烧成品固件（`t113_v12_bt.img`）+ 用 adb 操作板子，照样能学应用层（见文末附录 B） |

# 1. 硬件要求（照抄实测配置）

| 项目 | 实测配置（原环境） | **最低要求** | 说明 |
|---|---|---|---|
| CPU | 12 核（虚拟机给 8-12 核） | 4 核 | 编译靠并行，核越多越快 |
| 内存 | 16GB（虚拟机给 15GB） | **12GB** | 编译内核时吃内存，低于 8G 会 OOM |
| 磁盘 | 196GB（已用 64GB，剩 123GB） | **150GB 空闲** | SDK 39GB + 编译产物 + 系统 |
| 硬盘类型 | SSD | **必须 SSD** | 机械硬盘编译会慢 5-10 倍 |
| 系统 | Windows 10/11 | 同 | VirtualBox 支持 |

> **为什么要虚拟机而不是直接装双系统**：虚拟机可以打快照，编译环境炸了一键回滚；还能随时删掉不留痕迹。

# 3. 第①步：安装 VirtualBox

1. 打开 <https://www.virtualbox.org/wiki/Downloads> → 下载 **Windows hosts** 安装包
2. 双击安装，一路默认（会短暂断网，正常）
3. 装完**重启电脑**（驱动生效）
4. 打开 VirtualBox，能看到主界面即可

> ⚠️ 如果 Windows 开了"智能应用控制 / 内核隔离"，可能拦截安装：设置 → 隐私和安全性 → Windows 安全中心 → 应用和浏览器控制 → 关闭后重试。

---

# 4. 第②步：安装 Ubuntu 24.04

## 4.1 下载镜像（国内加速）

推荐**阿里云镜像**（比官网快很多）：

```
https://mirrors.aliyun.com/ubuntu-releases/24.04/ubuntu-24.04.3-desktop-amd64.iso
```

> 版本说明：24.04.x 都行；**实测 24.04.4 编译通过**。不要用 25.x（太新，SDK 里老工具链可能报错）。
> 下载后文件约 6GB。

## 4.2 新建虚拟机

VirtualBox 主界面 → **新建**：

| 设置项 | 填什么 |
|---|---|
| 名称 | `t113-ubuntu` |
| 类型 / 版本 | Linux / Ubuntu (64-bit) |
| 内存 | **12288 MB（12G）**，物理机内存 16G 就填 12288；32G 可填 16384 |
| 处理器 | **8 核**（物理机核数的一半到八成全给，但别把物理机核数全占） |
| 硬盘 | **200 GB**，选"动态分配"（不会立刻占满） |
| 显存 | 设置 → 显示 → 显存拉到 **128MB**，关闭 3D 加速 |

## 4.3 安装系统

1. 设置 → 存储 → 光盘图标 → 选择下载的 iso
2. 启动虚拟机，选 **Try or Install Ubuntu** → 语言选中文（或 English 都行）
3. 安装类型：**最小安装**（Minimal），**取消勾选**"安装第三方软件"（省时间，后面手动装）
4. 分区：选 **清除整个磁盘并安装**（这是虚拟机，放心）
5. 用户名/密码：**用户名用英文小写**（如 `karry`），密码记好
6. 等 15-20 分钟 → 重启 → 进桌面

## 4.4 安装增强功能（剪贴板互通 + 分辨率自适应）

虚拟机窗口菜单 → **设备 → 安装增强功能** → 桌面弹出光盘 → 打开终端执行：

```bash
sudo apt update
sudo apt install -y build-essential linux-headers-$(uname -r)
cd /media/$USER/VBox_GAs_*/ && sudo ./VBoxLinuxAdditions.run
```

装完**重启虚拟机**。然后：虚拟机设置 → 常规 → 高级 → 共享剪贴板选"**双向**"、拖放选"双向"。

> 剪贴板还是不通？见《常见错误》第 8 条。

# 5. 第③步：设置端口转发（方便从 Windows 操作）

关机状态下：设置 → 网络 → 网卡 1（NAT）→ **高级 → 端口转发** → 添加：

| 名称 | 协议 | 主机端口 | 子系统端口 |
|---|---|---|---|
| ssh | TCP | **2222** | **22** |

这样以后在 Windows 终端里 `ssh -p 2222 用户名@127.0.0.1` 就能进虚拟机，**复制粘贴命令比在虚拟机窗口里方便得多**。

# 6. 第④步：换国内镜像源（提速关键）

打开虚拟机终端：

```bash
# 备份原配置
sudo cp /etc/apt/sources.list.d/ubuntu.sources /etc/apt/sources.list.d/ubuntu.sources.bak 2>/dev/null
sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak 2>/dev/null
```

Ubuntu 24.04 用的是新格式（`ubuntu.sources`），直接用命令替换成阿里云：

```bash
sudo sed -i 's|http://archive.ubuntu.com/ubuntu|https://mirrors.aliyun.com/ubuntu|g; s|http://security.ubuntu.com/ubuntu|https://mirrors.aliyun.com/ubuntu|g; s|http://cn.archive.ubuntu.com/ubuntu|https://mirrors.aliyun.com/ubuntu|g' /etc/apt/sources.list.d/ubuntu.sources
sudo apt update
```

✅ 成功标志：`apt update` 几秒内完成，速度显示 `mirrors.aliyun.com`。

> 如果还是慢，换清华源：把上面命令里的 `mirrors.aliyun.com` 换成 `mirrors.tuna.tsinghua.edu.cn`。

# 7. 第⑤步：安装编译依赖（这是实测清单）

```bash
sudo apt install -y \
  build-essential gcc g++ make cmake \
  bison flex gawk bc cpio rsync unzip zip texinfo gettext \
  python3 python3-pip \
  device-tree-compiler u-boot-tools squashfs-tools \
  libxml-parser-perl libncurses-dev libssl-dev libelf-dev zlib1g-dev \
  liblz4-tool git subversion
```

> **这份清单的来源**：从原编译成功的机器上导出的已装包（`dpkg -l` 实查），不是网上抄的。
> 其中 `bc bison build-essential cpio device-tree-compiler flex g++ gawk gcc gettext libxml-parser-perl make python3 python3-pip rsync squashfs-tools texinfo u-boot-tools unzip zip` 是**原机器确认已装**的；其余（`libncurses-dev libssl-dev libelf-dev zlib1g-dev liblz4-tool cmake`）是常见编译依赖，多装无害。

✅ 验证：

```bash
gcc --version | head -1      # 应显示 gcc 13.x
make --version | head -1
dtc --version
```

# 8. 第⑥步：装 SSH 服务（强烈建议）

```bash
sudo apt install -y openssh-server
sudo systemctl enable --now ssh
ip addr | grep 192.168     # 记下虚拟机 IP（NAT 模式下无所谓，走端口转发）
```

然后回到 **Windows** 终端测试：

```bash
ssh -p 2222 你的用户名@127.0.0.1
```

能登进去 = 成功。**以后所有编译操作都在这个 SSH 窗口里做**（复制粘贴方便、可调字体、可缩小窗口）。

> 注意：这个 SSH 是**密码登录**（用你装系统时设的密码），不是密钥。

# 9. 第⑦步：把 SDK 传进虚拟机（11GB）

## 9.1 关键原则

- SDK 解压后的路径必须是：`/home/你的用户名/T113-Tina5.0-V1.2`
- **路径里不能有中文、不能有空格**（原文件夹名 `T113_Tina5.0 V1.2` 中间有空格，先改成 `T113_Tina5.0-V1.2`）

## 9.2 三种传法（按情况选）

### 方法 A：共享文件夹（最简单，推荐）

1. 虚拟机**关机** → 设置 → 共享文件夹 → 添加：
   - 文件夹路径：`D:\BaiduNetdiskDownload`
   - 文件夹名称：`share`
   - 勾选"自动挂载"和"固定分配"
2. 开机后在虚拟机里：

```bash
ls /media/sf_share/          # 能看到 D:\BaiduNetdiskDownload 的内容
```

> 首次访问可能提示"没有权限"：把当前用户加入 vboxsf 组，然后**重新登录**：
> ```bash
> sudo usermod -aG vboxsf $USER
> ```
> 注销再登录（或重启）生效。

### 方法 B：从 Windows 用 scp 推（适合已开 SSH）

Windows PowerShell：

```powershell
scp -P 2222 "D:\BaiduNetdiskDownload\T113_Tina5.0-V1.2.tar.gz" 用户名@127.0.0.1:/home/用户名/
```

### 方法 C：重新下载

如果 SDK 是压缩包且原电脑已不在：找课程资料包的网盘重新下载（Tina5.0 V1.2，11GB）。

## 9.3 拷贝 + 解压

```bash
# 假定通过共享文件夹
cp /media/sf_share/T113_Tina5.0-V1.2.tar.gz ~/     # 如果已经是目录，直接 cp -r
cd ~
tar -xzf T113_Tina5.0-V1.2.tar.gz                  # 解压约 10-20 分钟
# 如果拷的是目录：
# cp -r /media/sf_share/T113_Tina5.0\ V1.2 ~/T113-Tina5.0-V1.2
```

✅ 验证目录结构（应看到这些）：

```bash
ls ~/T113-Tina5.0-V1.2
# build.sh  device  kernel  openwrt  out  platform  brandy  ...
du -sh ~/T113-Tina5.0-V1.2        # 约 39GB（含 out）或 ~32GB（未编译）
```

> **文件完整性**：如果原电脑有 md5，先比对 `md5sum 文件`。没有就靠 `tar -tzf` 能否完整列出判断。

# 10. 第⑧步：检查交叉工具链

SDK 自带 ARM 交叉编译器，不需要单独装：

```bash
ls ~/T113-Tina5.0-V1.2/openwrt/openwrt/staging_dir/toolchain/bin/ | head
# 应看到 arm-openwrt-linux-gnueabi-gcc-8.3.0 等
```

如果没有短名 `arm-openwrt-linux-gcc`，补一个软链接（编译 bluealsa 时才需要）：

```bash
cd ~/T113-Tina5.0-V1.2/openwrt/openwrt/staging_dir/toolchain/bin/
ln -sf arm-openwrt-linux-gnueabi-gcc-8.3.0 arm-openwrt-linux-gcc
```

# 11. 第⑨步：首次编译（30-40 分钟）

```bash
cd ~/T113-Tina5.0-V1.2
./build.sh
```

✅ 成功标志：最后出现 **`build OK`**。

**编译期间会看到什么**：大量 `CC`、`LD`、`AR` 行滚动，属正常。中途不要关窗口、不要休眠电脑。

**加速技巧**（如果只重编局部）：

- 官方 `build.sh` 默认已并行，不要手动改 -j
- 关闭虚拟机的 3D 加速、关闭 Windows 的省电休眠
- 首次编译后**打快照**（见第 13 节），以后改坏了直接回滚，不用重编 40 分钟

**首次编译常见错误**：

| 报错 | 原因 | 解决 |
|---|---|---|
| `fatal error: curses.h: No such file` | 缺 ncurses | `sudo apt install libncurses-dev` |
| `error: openssl/ssl.h: No such file` | 缺 openssl 头 | `sudo apt install libssl-dev` |
| `Killed` / 编译中途进程消失 | **内存不足**（OOM） | 虚拟机内存加到 12G；或减少并行 |
| `No space left on device` | 磁盘满 | 虚拟机磁盘调到 200G |
| `Permission denied` | 用了 sudo 编译 | **不要 sudo**，用普通用户 |
| `python: command not found` | Ubuntu 24 只有 python3 | `sudo apt install python3` 并建软链：`sudo ln -sf /usr/bin/python3 /usr/bin/python` |

# 12. 第⑩步：打包出固件

```bash
cd ~/T113-Tina5.0-V1.2
source build/envsetup.sh
pack
```

✅ 成功：出现 **`pack finish`**，产物在：


**烧录流程**（固定）：PhoenixSuit → 一键刷机 → 选 img → 勾全盘擦除升级 → 板子断电 → **按住 LOAD** → 插 DEBUG 线 → 叮咚后 3 秒松手。

# 13. 稳定运行策略（强烈建议照做）

| 策略 | 怎么做 | 为什么 |
|---|---|---|
| **装完就快照** | VirtualBox → 虚拟机 → **生成备份（快照）**，命名"干净环境-已编译" | 编译环境炸了一键回滚，省 40 分钟 |
| 改配置前再快照 | 每次大改前再拍一个 | 改错了能退 |
| 不要用 sudo 编译 | 全程普通用户 | sudo 编译会产生 root 属主文件，后续编译报权限错 |
| 关机用正常关机 | 虚拟机关机菜单，不要直接关窗口 | 直接关可能损坏文件系统 |
| 定期清理 | `./build.sh clean`（谨慎，会清产物） | 磁盘会涨 |
| 磁盘留 30% 空闲 | 监控 `df -h` | 磁盘满会导致编译失败 |

# 14. 常见错误对照表

| # | 症状 | 原因 | 解决 |
|---|---|---|---|
| 1 | 虚拟机启动黑屏、SSH 连不上 | 偶发启动卡死 | 强制关机重启虚拟机；还不行重启物理机 |
| 2 | `ssh` 报 Permission denied (publickey) | 用了密钥认证但没配 | 改用密码：`ssh -o PreferredAuthentications=password 用户名@127.0.0.1 -p 2222` |
| 3 | Windows→虚拟机剪贴板不生效 | 增强功能没装或进程没跑 | 装增强功能；虚拟机内执行 `VBoxClient --clipboard`；或写 `~/.config/autostart/vboxclient-clipboard.desktop` 自启 |
| 4 | 共享文件夹提示无权限 | 用户不在 vboxsf 组 | `sudo usermod -aG vboxsf $USER` 后重新登录 |
| 5 | `apt update` 很慢 | 没换源 | 第 6 步换阿里云/清华源 |
| 6 | 编译报 `Killed` | 内存不足 | 虚拟机内存加到 12G |
| 7 | 编译报 `No space left` | 磁盘不足 | 扩容虚拟磁盘（见下） |
| 8 | 路径含中文/空格导致奇怪错误 | SDK 放在中文路径 | 移到 `/home/用户名/` 下，英文无空格 |
| 9 | 编译时报权限错误 | 曾用 sudo 编译过 | `sudo chown -R $USER:$USER ~/T113-Tina5.0-V1.2` |
| 10 | `python: not found` | 24.04 只有 python3 | `sudo ln -sf /usr/bin/python3 /usr/bin/python` |
| 11 | 交叉编译报 `STAGING_DIR not set` | 工具链 wrapper 要求 | `export STAGING_DIR=~/T113-Tina5.0-V1.2/openwrt/openwrt/staging_dir/target` |
| 12 | 编译很慢 | 机械硬盘/核数少 | 换 SSD、虚拟机调 8 核 |
| 13 | 虚拟机窗口不能调分辨率 | 没装增强功能 | 装 VirtualBox Guest Additions |
| 14 | 时间不对导致下载证书错误 | 时区 | `sudo timedatectl set-timezone Asia/Shanghai` |

**虚拟磁盘扩容**（第 7 条）：

```bash
# 在 Windows（VirtualBox 目录）：
VBoxManage modifyhd "路径\t113-ubuntu.vdi" --resize 204800   # 200GB，单位 MB
# 然后在虚拟机里用 GParted（Ubuntu 安装盘启动）扩展分区
```

2. Windows 装 adb（`05-工具与脚本/flash_tools`），用 `adb shell` 操作板子

4. 学习靠文档（`01-核心文档`），读代码靠 GitHub 网页
5. **想编译时**：借一台有 16G 内存的电脑，或租云服务器（按小时计费，拷 SDK 上去编译）
