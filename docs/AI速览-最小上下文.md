## 1. 项目一句话

在 **Ubuntu** 下搭 ARM 交叉编译环境，对一块**非官方参考设计**的全志 **T113-S3** 开发板做板级适配（移植）：调试串口 → GPIO/LED/按键 → I2C 触摸 → MIPI 屏幕 → 音频输出 → 麦克风 → WiFi → 蓝牙（SPP 串口回显 + 手机 A2DP 放歌）→ LVGL 图形界面。9 项全通，解决 40+ 真实问题。**本质：让软件配置匹配实际硬件。**

## 2. 硬件速查（面试必背）

| 部件 | 关键值 |
|---|---|
| 主控/系统 | T113-S3，Tina Linux 5.0，内核 5.4.61 |
| 调试串口 | UART3：**PB6/PB7**，115200，功能号 **7** |
| LED/按键 | **PD11** 高电平亮 / **PD10** 按下为低（全局号 107/106） |
| 触摸 | GT9xx @ **TWI1**，**PE0/PE1**，地址 **0x5D**，INT=PE5，RST=PE4，event5 |
| 屏幕 | FL7707N MIPI **4 lane**，**720×1424**，fb0 32bpp 双缓冲 |
| 功放 | LM4871，使能 **PB2=gpio34**，**低电平=工作**（SHDN 高=关断） |
| 麦克风 | 板载驻极体，MIC3 差分输入 |
| WiFi/蓝牙 | RTL8723DS：WiFi 走 SDIO（`024c:d723`），蓝牙走 **UART1 PG6/PG7**（H5） |

## 3. 九关核心（改动点 + 关键坑）

| 关卡 | 改什么 | 关键坑 |
|---|---|---|
| ① 串口 | env.cfg（earlycon 地址 `0x02500C00`）、sys_config.fex、board.dts 三处 | 三阶段各读各的配置；软链接陷阱（验证和编译读两个文件） |
| ② LED/按键 | config-5.4 开关 + dts 两节点 | `GPIO_KEYS` 是幽灵符号，真开关只有 `KEYBOARD_GPIO`；设备名是 `gpio-keys` 不是 label |
| ③ 触摸 | **只在 board.dts**：删幽灵 ctp@14、PE14/15→PE0/1、关 twi2 | 枚举≠应答；控制器对≠线对；能力≠接线 |
| ④ 显示 | U-Boot defconfig + `.config` 关 `CONFIG_BOOT_GUI`；fb 尺寸 720×1424 | `lcd_used` 不是开关；U-Boot 抢先开屏，内核礼让 |
| ⑤ 喇叭 | 无驱动改动：sysfs 拉低 gpio34 + amixer | SHDN **高=关断**（手册 p11），"使能脚拉高"直觉错 |
| ⑥ 麦克风 | 零配置（MIC3 预设匹配） | 命令没报错≠录到：看峰值/RMS |
| ⑦ WiFi | 四层：config `RTL8723DS=m`、modules.mk 定义包、defconfig 勾选、rfkill 改 okay | 裸 .ko 不进系统；中文 SSID 被丢字 |
| ⑧ 蓝牙 | bt_up.sh：删 config、五条件、sdptool 注册 | 配对≠连接；**配对快照**；A2DP 五层坑；带宽 10.2 vs 41KB/s |
| ⑨ LVGL | SDK 自带 lvgl-8 源码直编，只改 EVDEV_NAME→event5 | 无屏用 fb0 dump 验证；换屏只需 5 分钟清单 |

## 4. 五个最值钱的技术点（按面试价值排序）

1. **带宽算账**：链路实测 **10.2 KB/s** vs 立体声需求 **41 KB/s**（4 倍差距）→ 排除驱动（overrun=0）→ 读源码发现 `--a2dp-force-mono` 只改 source 端 → 改 `a2dp.c` 收窄 sink 能力（单声道 + bitpool 12→10，约 8KB/s 留 20% 余量）→ 流畅。验证只认 btmon 的 `Maximum Bitpool`。
2. **配对快照**：对端 profile 列表 = 配对那一刻的 SDP 快照；板子事后补服务对方不知道 → **先修服务，再删配对重配**（全书出现 3 次）。
3. **查源码纠错**：`CONFIG_GPIO_KEYS` 内核源码里不存在（grep 零输出），真正需要 `CONFIG_KEYBOARD_GPIO`（只依赖 GPIOLIB）。
4. **无屏验证**：`cat /dev/fb0` → 720×1424×4 BGRA 解码成 PNG 验证 LVGL 渲染；fd 指向 /dev/fb0 与 event5 证通路。
5. **软链接陷阱**：`sed -i` 改软链接会销毁链接生成普通文件 → "验证和编译读的是两个文件"。

## 5. 十条方法论（每条一句）

1. 敲命令前看提示符（VM/Windows/板子三终端）
2. 配置与硬件不符就改配置——这就是移植
3. 改设备树前确认不是软链接
4. 板上写完必 `sync`；自启脚本 /etc 与 /root 双份并写进 SDK
5. 内核开关无效 = 依赖没满足或符号不存在（查 Kconfig）
6. 认设备认 Name，不认"谁在动"
7. 名字骗人——去读解析它的代码
8. 命令没报错 ≠ 功能正常，验证看数据
9. 对端功能列表是配对快照——先修服务再重配
10. 先算账再动手，数字给方向
