## 2. 三组必背数字（有数字 = 真做过）

| 数字 | 含义 |
|---|---|
| **10.2 KB/s vs 41 KB/s** | 蓝牙音频卡顿：串口链路实际吞吐只有立体声需求的 1/4，数据饿死。这是整个项目最亮的定量分析 |
| **bitpool 12 → 10；约 8 KB/s；20% 余量** | 解法：修改音频协商程序让板子只广播单声道低码率，流量压到 8KB/s，留两成余量后流畅 |
| **9 项外设 / 40+ 问题 / 15 个蓝牙问题** | 项目规模 |

补充弹药：屏幕 720×1424 / MIPI 4 lane / 32bpp 双缓冲；显示引擎 fps 51.5；芯片假死需断电 15 秒。

## 3. 五个技术亮点（每个准备 3 句话）

### 亮点一：带宽算账（最推荐讲）
- 现象：手机连板放歌卡顿。
- 做法：先量化——`hciconfig` RX 字节 8 秒差值测得 **10.2 KB/s**，对比立体声 SBC 需求 **41 KB/s**，判断管道只有 1/4，排除驱动错误（overrun/HCI 计数为 0）。提速路线失败后改降流量：读 bluealsa 源码发现单声道参数只作用于 source 端，改 sink 端能力声明（`a2dp.c` 三行），让手机按 A2DP 规范只能选低码率。
- 结果：流畅；音质降为"电话音质"，是 10KB/s 管道下的理性取舍。验证只认 btmon 协商参数。

### 亮点二：配对快照机制（展示排查深度）
- 手机蓝牙连不上音箱，剥五层：缺配对应答员 → 应答能力声明错 → 音频服务注册丢失 → 对端缓存旧服务列表 → BlueZ 兼容模式不自动生成音频 SDP 记录。
- 每层都靠 `btmon` 抓包实锤。
- 沉淀规律：**对端的 profile 列表是配对那一刻的 SDP 快照**，必须先修板子服务、再删配对重配。

### 亮点三：查源码纠正结论（展示严谨）
- 内核配置加了没效果，不靠"多试几个"，去源码查：`CONFIG_GPIO_KEYS` **根本不存在**（写入被静默丢弃），真正需要的是 `CONFIG_KEYBOARD_GPIO`。
- 方法固化：查 Kconfig 的 `depends on` 和符号是否存在。

### 亮点四：无屏验证（展示工程巧思）
- 屏幕硬件暂缺，先把 LVGL 移植完：把 `/dev/fb0` 显存整块 dump 回电脑，按 720×1424×BGRA 解码成图片，验证界面渲染正确；再用文件描述符（fd→/dev/fb0、fd→/dev/input/event5）和 CPU 时间确认通路接入。
- 换屏后零改动直接显示。

### 亮点五：软链接陷阱（展示复盘能力）
- 改了设备树却不生效：`sed -i` 修改软链接会销毁链接生成普通文件——**验证和编译读的是两个文件**。
- 固化成铁律：改真身、看 mtime、用 Python 穿透链接。

## 4. 高频追问 · 一句话答案

| 追问 | 答案 |
|---|---|
| 什么是"移植"？ | 官方 BSP 配的是评估板，我的板硬件不同（串口脚、触摸总线、WiFi 芯片都不同），改软件配置去匹配实际硬件 |
| 为什么串口要改三个文件？ | 启动分三段：U-Boot 读 FEX、内核读设备树、earlycon 要寄存器地址；少改一处日志就断一段 |
| 设备树怎么和驱动对上？ | `compatible` 字符串与驱动源码里的 of_match_table 一字不差匹配，内核调用驱动 probe |
| 中断里为什么不能睡眠？ | 中断上下文不属于任何进程，睡眠会把 CPU 卡死；耗时活给下半部（工作队列可以睡，tasklet 不行） |
| 进程和线程区别？ | 进程是资源分配单位（独立地址空间），线程是调度单位（共享地址空间，切换只换寄存器和栈） |
| 怎么保证验证可信？ | 命令没报错 ≠ 功能正常：录音看峰值/RMS、显示看分辨率数字、网络看链路→IP→ping 三层、蓝牙只认抓包协商参数 |
| 遇到最难的问题？ | 讲亮点一（带宽算账），或者亮点二（五层洋葱） |
| 你写过驱动吗？ | **诚实**：没有从零写过字符设备驱动，做的是驱动适配与配置；理解设备树、probe、中断下半部机制，手写驱动是下一步要补的 |
| 会 ROS2 吗？ | 正在学，了解话题/服务/动作、DDS 与 QoS；Linux 底层经验能直接迁移（DDS 底层就是 IPC+网络） |
| 为什么用 Ubuntu？ | 机器人工具链（ROS2、SDK、交叉编译）都以 Ubuntu LTS 为标准；我在 Ubuntu 里完成全部编译、SSH 远程操作和脚本自动化 |

## 5. 机器人方向补充（面试官可能顺着问）

| 主题 | 一句话 |
|---|---|
| 软/硬实时 | 硬实时超时=事故（电机控制环），软实时可偶尔超时（视频）；标准 Linux 是软实时 |
| PREEMPT_RT | 把内核不可抢占区改小（中断线程化、自旋锁实时化），不提升平均性能，但把**最坏延迟**从几十毫秒压到几十微秒且可预测 |
| 优先级反转 | 低任务持锁→高任务等锁→中任务插队；解法是**优先级继承**。1997 火星探路者号因此反复重启 |
| ROS2 三种通信 | 话题=数据流（相机/雷达）、服务=一问一答（查电量）、动作=长任务带反馈可取消（导航） |
| QoS 兼容规则 | **订阅端的要求 ≤ 发布端能提供的**；BestEffort 发布 + Reliable 订阅 = 收不到（静默） |
| ROS2 收不到消息排查 | 同 DOMAIN_ID → QoS 兼容 → 组播是否被挡 → 时间同步 |
| 机器人软件骨架 | 传感器驱动 → 感知 → 规划 → 控制 → 硬件抽象（CAN/串口） |
