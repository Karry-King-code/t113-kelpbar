# T113 KelpBar · 嵌入式 Linux 全流程实战

> 一块**非官方参考设计**的全志 T113-S3 开发板，从零完成 **9 项外设 / 功能**的板级适配：
> 调试串口 → LED/按键 → I2C 触摸 → MIPI 屏幕 → 音频输出 → 麦克风 → WiFi → 蓝牙（串口回显 + 手机连板放歌）→ LVGL 图形界面。
> 解决 **40+ 个真实问题**，每个都有「症状 → 证据 → 根因 → 解法」记录。
>
> **项目的本质是"移植"**：官方 BSP 的配置是给评估板做的，本板硬件接线不同——**让软件配置匹配实际硬件**。

## 🔧 硬件速查

| 部件 | 值 |
|---|---|
| 主控 / 系统 | 全志 T113-S3 / Tina Linux 5.0（内核 5.4.61） |
| 调试串口 | UART3：**PB6(TX) / PB7(RX)**，115200-8N1，座子 U24 |
| LED / 按键 | **PD11**（高电平亮）/ **PD10**（按下为低） |
| 触摸 | GT9xx @ **TWI1**，**PE0(SCL)/PE1(SDA)**，地址 **0x5D**，INT=PE5，RST=PE4 |
| 屏幕 | FL7707N MIPI **4 lane**，**720×1424**，座子 FPC2 |
| 功放 | LM4871，使能脚 **PB2（全局 34）**，**低电平=工作**，喇叭座 CN2 |
| 麦克风 | 板载驻极体 GMI4015P，MIC3 差分输入 |
| WiFi / 蓝牙 | RTL8723DS（SDIO / UART1@PG6,PG7） |

## 💡 五个最值得讲的技术点（面试弹药）

1. **带宽算账**：蓝牙音频卡顿，实测链路 **10.2 KB/s** vs 立体声需求 **41 KB/s**（4 倍差距），排除驱动错误后改 sink 协商码率（bitpool 12→10，约 8KB/s 留 20% 余量）→ 流畅。
2. **配对快照机制**：对端 profile 列表是**配对那一刻**的 SDP 快照——先修板子服务，再删配对重配。
3. **查源码纠错**：`CONFIG_GPIO_KEYS` 内核里根本不存在，真正需要的是 `CONFIG_KEYBOARD_GPIO`。
4. **无屏验证**：把 `/dev/fb0` 显存 dump 回电脑解码成图片，验证 LVGL 渲染。
5. **软链接陷阱**：`sed -i` 改软链接导致"验证和编译读的是两个文件"。

## 🧠 十条方法论（每条都有事故背书）

1. 敲命令前先看提示符——VM/Windows/板子三个终端能力不同
2. 配置和硬件对不上就改配置——这就是移植
3. 改设备树前确认不是软链接；改完看 mtime
4. 板上写完文件必 `sync`；自启脚本 /etc 与 /root 双份 + 写进 SDK
5. 内核开关加了没效果 = 依赖没满足或符号不存在
6. 认设备要认名字，不要认"谁在动"
7. 名字骗人——配置是不是开关，去读解析它的代码
8. 命令没报错 ≠ 功能正常——验证看数据
9. 对端的功能列表是配对那一刻的快照——先修服务再重配
10. 出问题先算账再动手，数字会告诉你方向
