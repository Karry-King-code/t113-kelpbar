## 第 1 部分：硬件事实

### 板载麦克风（原理图第 5 页 AUDIO 页，实锤）

| 项目 | 值 |
|---|---|
| 麦克风型号 | **GMI4015P-2C**（4mm 驻极体麦克风，灵敏度 -42dB） |
| 外观 | **金色圆形金属壳**（就是你问的那个"圆圆的"） |
| 位置 | 板子正面，丝印 `MIC` 旁（KEY 按键右边） |
| 供电 | AVCC 经 R148(750Ω) 偏置 |
| 信号输出 | C85/C86(100nF) 耦合 → **MIC_IN_3P / MIC_IN_3N** |
| 进入主控 | 引脚 87(MICIN3P) / 88(MICIN3N) —— T113 内置 audiocodec |

> **原理图符号就是经典的驻极体麦克风画法**：圆形带 `+` `-` 两个脚。
> **驻极体麦克风需要偏置电源**（R148 提供），这是它和 MEMS 麦克风的重要区别。

### 声卡事实（与喇叭共用一颗 audiocodec）

```
            ┌────────── T113 内置 audiocodec ──────────┐
MIC3(板载) →│ MIC3 → ADC3 → 数字音频 → Capture 设备    │ → 内存(录)
            │ 内存(放) → 数字音频 → DAC → HPOUT        │ → 功放LM4871 → 喇叭
            └───────────────────────────────────────────┘
```

**录和放共用 `/dev/snd/` 里的同一张声卡（card 0）**，但走不同子设备：
- playback（放）：`pcm0p`
- capture（录）：`pcm0c`

### 混音器配置（rc.local 出厂预设，已生效）

```
MIC3 Input Select = 1     ← 输入选 MIC3（对差分输入的通道选择）
MIC3 Switch       = on    ← MIC3 通路开关
ADC3 Gain         = 19    ← 录音增益（0~31，出厂 19 中等偏上）
```

**arecord 常用参数**：

|---|---|
| `-f S16_LE` | 采样格式：有符号 16 位小端（最通用） |

| `-c 1` | 单声道 |
| `-d 5` | 录 5 秒 |
| `文件名.wav` | 输出 WAV 文件 |

**本关标准命令**：

```sh
arecord -f S16_LE -r 16000 -c 1 -d 5 /root/audio/test_rec.wav
```

## 第 3 部分：怎么判断"录到了真声音"（数据说话）

**只看 `arecord` 不报错是不够的** —— 麦克风坏了/通路错了，它照样安静地"录"5 秒全零。

**正确方法：把录音拉回来，用数据验证**：

```python
import wave, struct, math
w = wave.open('test_rec.wav','rb')
n = w.getnframes()
samples = struct.unpack('<%dh' % n, w.readframes(n))
peak = max(abs(s) for s in samples)                 # 峰值
rms = math.sqrt(sum(s*s for s in samples)/n)        # 均方根(平均能量)
nz = sum(1 for s in samples if abs(s) > 100)        # 活跃采样数
print(peak, rms, nz)
```

**判读表**：

| 指标 | 纯数字静音 | 真实环境音 | 说明 |
|---|---|---|---|
| peak | 0 | 数百~32767 | 有真实模拟信号 |
| rms | 0 | 数百 | 平均能量非零 |
| 活跃采样 | 0 | 大量 | 声音在起伏 |

**我实测的**：peak=32767（有瞬时爆音打满量程）、rms=393（底噪真实存在）、22 个活跃采样 —— **模拟信号真实被数字化了，麦克风通路工作** ✓。

> **金句**：**"命令没报错"≠"功能正常"。** 验证录音必须看数据内容，就像验证显示必须看屏幕。

## 第 5 部分：踩坑档案

| # | 症状 | 真因 | 解法 |
|---|---|---|---|
| 1 | `arecord` 成功但录的是静音 | 麦克风没坏也会"成功" —— 要用数据验证内容 | 拉回分析 peak/rms |
| 2 | 录音后立刻 `aplay` 报 `Device or resource busy` | **音乐循环还在跑**（while true 会不停重启 madplay） | 先杀循环 shell 再杀播放器 |
| 3 | 只 `killall` 杀不干净 | `killall` 杀了 madplay，但 while-true 循环 shell 又把它拉起来 | **连循环 shell 一起杀**：`for p in $(ps \| grep 'while true' ...); do kill $p; done` |
| 4 | `tinycap: not found` | 本固件用标准 ALSA 不是 tinyalsa | 用 `arecord` |
| 5 | 录的音全是"嗡嗡"底噪 | 增益太高或环境太吵 | 调 `ADC3 Gain`（0~31） |
| 6 | 回放声音很小 | `ADC3 Gain` 太低（录音侧） | 调到 19~25 |

> ### ⭐ 第 2、3 项是本关的独有坑（喇叭关没有的）
> **声卡是录放共用的**。音乐在放，录音/回放都会被打断。
> **杀进程要连"父循环"一起杀** —— 只杀播放器，循环脚本马上把它再拉起来。

## 第 6 部分：常考问题

**Q1：麦克风是什么类型？为什么有个电阻接电源？**
A：GMI4015P 驻极体麦克风（ECM）。驻极体麦克风内部有 FET 场效应管，需要外部偏置电源（R148 750Ω 从 AVCC 供电）才能输出信号。MEMS 麦克风则不需要外部偏置。

**Q2：录音和放音能同时进行吗？**
A：这颗 audiocodec 有独立的 playback 和 capture 子设备（pcm0p/pcm0c），硬件上支持全双工。但软件上本固件的默认 ALSA 配置（dmix）下同时开需要额外配置，一般分开做。

**Q3：怎么证明录到的不是纯静音？**
A：把 WAV 拉回来分析数据：峰值振幅、RMS 均方根、活跃采样数。纯数字静音这三项全是 0；真实录音 rms 有几百、有采样起伏。（我实测 peak=32767、rms=393）

**Q4：采样率 16kHz 够吗？**
A：人声主要能量在 300~3400Hz，根据奈奎斯特采样定理，16kHz 采样率能还原 8kHz 以内的信号，对语音绰绰有余。要录音乐就上 44100/48000。

**Q5：为什么 MIC3 配置在 rc.local 里出厂就有？**
A：MIC3 Input Select/Switch/ADC3 Gain 是板级方案的预设（评估板也用 MIC3）。说明这块板的音频输入设计就是走 MIC3 差分输入。
