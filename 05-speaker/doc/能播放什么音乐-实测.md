# 板子上能播放什么音乐？—— 实测回答

> 本文回答一个问题：**这块板子能放什么格式的音乐？怎么放？**
> 所有结论都是**实测得出**，不是推测。

---

## 一、先分清三种"声音"

排查问题时，**用测试音比用音乐更容易定位问题**。

| 类型 | 文件 | 声音 | 用途 |
|---|---|---|---|
| **测试音** | `test_440.wav` | "嘟——"（440Hz 单音，标准音 A） | **判断通路对不对** |
| **测试音** | `test_scale.wav` | 音阶 do-re-mi-fa-so-la | 判断音高是否正常 |
| **简单音乐** | `music_twinkle.wav` | 小星星（合成音色） | 判断能连续播放 |
| **真实音乐** | `*.mp3` | 真正的歌曲 | 验收效果 |

> **为什么要用测试音？**
> 听到 440Hz 就知道"通路完全正确"；直接放歌的话，声音不对你分不清是**解码问题**还是**喇叭问题**。

## 二、能放什么格式？（实测）

### 默认固件（`t113_v7_speaker.img`）

板子上只有 `aplay`，它支持的格式：

| 格式 | 支持 | 说明 |
|---|---|---|
| **WAV** | ✅ | 无损，但体积大 |
| RAW / AU / VOC | ✅ | 冷门 |
| MP3 | ❌ | **不支持** |
| FLAC / AAC / OGG | ❌ | 不支持 |

**结论**：只能放 WAV。

### 新固件（`t113_v8_music.img`）★ 推荐

我开启了 SDK 自带的 MP3 播放器 **madplay**，现在支持：

| 格式 | 支持 |
|---|---|
| **MP3** | ✅ **新增** |
| WAV / RAW / AU / VOC | ✅ |

### MP3 vs WAV 体积对比（实测）

同样一段 8 秒的小星星：

| 文件 | 大小 | 倍数 |
|---|---|---|
| `music_twinkle.wav` | 705,644 字节 | 1× |
| **`music_twinkle.mp3`** | **129,192 字节** | **0.18×（省 82%）** |

> **这就是为什么要支持 MP3** —— 一首 4 分钟的 WAV 要 40MB，MP3 只要 4MB。
> 而板子的存储只有 8MB 可用空间。

## 三、怎么播放音乐？

### 播放 WAV

```sh
adb shell "aplay /root/audio/music_twinkle.wav"
```

### 播放 MP3（需 v8 固件）

```sh
adb shell "madplay /root/audio/music_twinkle.mp3"
```

**madplay 的输出含义**：

```
MPEG Audio Decoder 0.15.2 (beta)
308 frames decoded (0:00:08.0), -11.6 dB peak amplitude, 0 clipped samples
```

| 字段 | 含义 |
|---|---|
| `308 frames decoded` | 解码了 308 帧 |
| `(0:00:08.0)` | 时长 8 秒 |
| `-11.6 dB peak amplitude` | 峰值电平（正常，说明有信号输出） |
| `0 clipped samples` | 削波样本数（0 = 音质完好） |

> **`frames decoded` 有数字 + `peak amplitude` 不是 -inf = 解码成功且音频正常输出。**

### madplay 常用参数

| 参数 | 作用 |
|---|---|
| `madplay file.mp3` | 播放 |
| `madplay -v file.mp3` | 显示详细解码信息 |
| `madplay -q file.mp3` | 安静模式 |
| `madplay -o output.wav file.mp3` | **转成 WAV**（不播放） |
| `madplay -a -10 file.mp3` | 衰减 10dB（音量小一点） |
| `madplay -r file.mp3` | 循环播放 |

## 四、怎么把音乐放进板子？

### 步骤1：准备音乐文件

**方式 A：用现成的 MP3**

把任意 `.mp3` 推到板子：

```sh
MSYS_NO_PATHCONV=1 D:\t113_work\flash_tools\adb.exe push "D:\我的音乐\song.mp3" /root/audio/song.mp3
```

**方式 B：用 ffmpeg 转换**

如果手上有其他格式（flac/m4a/wav），用 ffmpeg 转 MP3：

```sh
# Windows 上（已装 ffmpeg）
ffmpeg -i input.flac -codec:a libmp3lame -b:a 128k output.mp3
```

**方式 C：自己合成一段旋律**（不需要音频素材）

```python
import struct, math, wave

# 音符频率表
N = {'C4':261.63,'D4':293.66,'E4':329.63,'F4':349.23,'G4':392.00,'A4':440.00}
# 小星星的简谱
song = [('C4',0.5),('C4',0.5),('G4',0.5),('G4',0.5),('A4',0.5),('A4',0.5),('G4',1.0),
        ('F4',0.5),('F4',0.5),('E4',0.5),('E4',0.5),('D4',0.5),('D4',0.5),('C4',1.0)]

rate = 44100
data = bytearray()
for note, dur in song:
    f = N[note]; n = int(rate*dur)
    for i in range(n):
        t = i/rate
        env = 1.0
        if i < rate*0.01: env = i/(rate*0.01)          # 快起音
        elif i > n - rate*0.05: env = (n-i)/(rate*0.05) # 缓衰减
        # 基频 + 泛音 = 更像乐器
        v = math.sin(2*math.pi*f*t) + 0.3*math.sin(2*math.pi*2*f*t) + 0.15*math.sin(2*math.pi*3*f*t)
        data += struct.pack('<h', int(32767*0.35*env*v/1.45))

with wave.open('music.wav','wb') as w:
    w.setnchannels(1); w.setsampwidth(2); w.setframerate(rate)
    w.writeframes(bytes(data))
```

然后用 ffmpeg 转 MP3：

```sh
ffmpeg -i music.wav -codec:a libmp3lame -b:a 128k music.mp3
```

### 步骤2：确认板子空间够

```sh
adb shell "df -h /root"
```

**我看到的**：

```
Filesystem      Size  Used Available Use% Mounted on
overlayfs     7.9M  700.0K      7.2M   9% /
```

> **只有 7.2MB 可用空间！**
> 所以 **MP3 不只是"方便"，是"必需"** —— WAV 一首歌就 40MB，根本放不下。

> **如果空间不够**：可以放 `/mnt/UDISK`（如果挂了 U 盘/SD 卡），或者用音频流（不推荐）。

### 步骤3：播放

```sh
adb shell "madplay /root/audio/music.mp3"
```

## 五、怎么把 MP3 支持加进固件（复刻步骤）

> 这一步我已经做完了（v8 镜像）。这里是**复刻方法**，供你理解或重做。

### 背景

SDK 里**自带** MP3 播放器包，只是默认没启用：

```
openwrt/package/feeds/sound/madplay/      ← madplay（MP3 播放器）
openwrt/package/feeds/libs/libmad/        ← libmad（MP3 解码库）
openwrt/package/feeds/libs/libid3tag/     ← libid3tag（读 MP3 标签）
```

### 步骤

**① 找对配置文件**（★ 关键 —— 容易改错文件）

包选择写在**目标板的 defconfig** 里：

```sh
T=~/T113-Tina5.0-V1.2
F=$T/openwrt/target/t113/t113-evb1_auto_nand/defconfig
```

> **踩坑**：我一开始改了 `openwrt/openwrt/.config`，**没用** —— 编译时会从 defconfig 重新生成。
> **要改 defconfig 才对。**

**② 查看当前状态**

```sh
grep -E 'PACKAGE_(libmad|libid3tag|madplay|alsa-lib)' $F
```

**我看到的**：

```
CONFIG_PACKAGE_alsa-lib=y          ← 已启用（aplay 靠它）
CONFIG_PACKAGE_libmad=y            ← 已启用
# CONFIG_PACKAGE_libid3tag is not set   ← 没开
# CONFIG_PACKAGE_madplay is not set     ← 没开（就是它）
```

**③ 开启缺的两个**

```sh
cp $F $F.bak-mp3
sed -i 's|^# CONFIG_PACKAGE_libid3tag is not set|CONFIG_PACKAGE_libid3tag=y|' $F
sed -i 's|^# CONFIG_PACKAGE_madplay is not set|CONFIG_PACKAGE_madplay=y|' $F
grep -E 'PACKAGE_(libid3tag|madplay)' $F    # 验证
```

**④ 编译**

```sh
cd ~/T113-Tina5.0-V1.2
./build.sh
source build/envsetup.sh
pack
```

> **注意**：编译时会**联网下载** madplay 源码（`madplay-0.15.2b.tar.gz`，约 590KB）。
> 如果 VM 不能联网会失败。

**⑤ 验证编进去了**

```sh
# 镜像体积应该变大
ls -la out/t113_linux_evb1_auto_nand_uart0.img

# rootfs 里应该能看到 madplay
ls out/t113/evb1_auto_nand/openwrt/build_dir/target/root-t113-evb1_auto_nand/usr/bin/ | grep madplay
```

**我实测的体积变化**：

| 镜像 | 大小 | 差值 |
|---|---|---|
| `t113_v7_speaker.img`（无 MP3） | 21,519,360 字节 | — |
| `t113_v8_music.img`（含 MP3） | 21,650,432 字节 | **+131,072 字节（128KB）** |

> **128KB 就是 madplay + libid3tag 的体积** —— 这是"真的编进去了"的物证。

## 六、实测验证记录

### MP3 播放实测（2026-10-09）

**测试文件**：`music_twinkle.mp3`（129,192 字节，小星星，8 秒，128kbps）

**命令**：

```sh
cd /root/audio && madplay music_twinkle.mp3
```

**输出**：

```
MPEG Audio Decoder 0.15.2 (beta) - Copyright (C) 2000-2004 Robert Leslie et al.
308 frames decoded (0:00:08.0), -11.6 dB peak amplitude, 0 clipped samples
real    0m 15.38s
```

**判读**：

| 指标 | 值 | 含义 |
|---|---|---|
| frames decoded | 308 | 解码成功 |
| 时长 | 8.0 秒 | 与原文件一致 |
| peak amplitude | -11.6 dB | **有信号输出**（不是 -inf） |
| clipped samples | 0 | 无失真 |

> **结论：MP3 解码链路完全打通。**

## 七、踩坑档案

| # | 症状 | 真因 | 解法 |
|---|---|---|---|
| 1 | `madplay: not found` | 固件没编进 madplay | 用 v8 镜像，或按第五部分开启 |
| 2 | 改 `.config` 编译无效 | **包选择在 target defconfig，不在 .config** | 改 `openwrt/target/t113/t113-evb1_auto_nand/defconfig` |
| 3 | 编译报 `LICHEE_TOP_DIR not defined` | 直接进 openwrt 子目录 make | 用顶层 `./build.sh` |
| 4 | 编译报 `LICHEE_IC not defined` | 环境变量不全 | 用顶层 `./build.sh`（它会设好） |
| 5 | `madplay: can't load library 'libid3tag.so.0'` | 缺库 | 确认 `CONFIG_PACKAGE_libid3tag=y` |
| 6 | 放歌没声音 | 功放极性搞反（SHDN 高电平=关断） | 见 `05-speaker` 文档的 PA_SHDN，**要拉低** |
| 7 | 空间不足推不进文件 | overlay 只有 7.2MB | 用 MP3（不是 WAV），或挂 U 盘 |
| 8 | `aplay` 播 MP3 报错 | aplay 不支持 MP3 | 用 `madplay` |

## 八、常用命令速查

```sh
# 播放 WAV
adb shell "aplay /root/audio/xxx.wav"

# 播放 MP3
adb shell "madplay /root/audio/xxx.mp3"

# 循环播放 MP3
adb shell "madplay -r /root/audio/xxx.mp3"

adb shell "madplay -o /root/audio/out.wav /root/audio/xxx.mp3"

# 看剩余空间
adb shell "df -h /root"

# 看板子上有什么播放器
adb shell "which aplay madplay mpg123"
```
